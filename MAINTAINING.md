# Maintaining Vocal Sessions

Notes for whoever works on the app next, whether that's Ivan, a new Claude session or anyone else. The [README](README.md) covers what the app does; this covers how it's built and how to change it safely.

---

## The short version

1. Change the files in `js/` and `css/` (or `index.html` for markup, `sw.js` for offline behaviour). Practice content (exercises, words, write-ups, goals) is all in `js/content.js`.
2. While building, run `python tests/run.py quick` (about a minute and a half) or just the files you're changing. Before pushing, run `python tests/run.py` (about 3½ minutes). Everything must pass.
3. Run `python tools/release.py 3.7` with the new version, and write the changes in `CHANGELOG.md`.
4. Run `python tests/run.py release` to check the version agrees everywhere.
5. Push to `main`. GitHub Pages publishes it within a minute or two, and the **Tests** check runs on GitHub.

**Working with Claude:** The call signs have separate meanings. **Render** approves the exact named scope; it does not start implementation or authorize a push. **Build** starts implementation only after that scope has Render approval. Build follows the checks and release steps below when applicable.
- Research, planning and prototyping may happen before approval, but do not edit the app in the repo until Ivan separately says **Build** for a Render-approved item.
- Each build happens in a **fresh chat**, started from a short [handoff note](HANDOFF.md). Implement only that approved scope; don't bundle other queue items.
- Tests are tiered: `quick` or single files while building, the full suite once before pushing. The full suite runs files side by side.

**Handoffs between chats and models:** [HANDOFF.md](HANDOFF.md) defines Recon, Blueprint, Render, Build and Debrief, with a template to copy. Queued app work and each item's gate status are in [RENDER_QUEUE.md](RENDER_QUEUE.md).
- Prepare a handoff when a stage ends (an idea agreed, a prototype approved, a build pushed), when switching between Gemini, ChatGPT and Claude, and before every fresh build chat.
- Start the next chat with it. The receiving model checks it against the repo (the code wins on what's built), confirms the required gates, then does only the next action it names. One model builds each change; the others explore or review.

### Every file has a version in its address

`index.html` loads `js/storage.js?v=3.7.1` and so on. A new version means new addresses, so no phone can mix an old file with a new page, and the offline copy can keep each version complete. `tools/release.py` updates every `?v=`; the release test fails if one is missed or a listed file doesn't exist. **Add a new file by adding its `<script>` (or `<link>`) to `index.html` with the same `?v=`.**

### Save safety (3.29, Q11)

Nothing the app does may lose saved data, a take or a session in progress without saying so.

- **Saved data that can't be read** (`load()`): when `vocalTracker` won't parse, isn't an object, or `cleanData()` fails, its text goes to `SAFE.rescue(text, 'unreadable')` and the app starts empty. When a song had to be dropped, the data as it was goes to `SAFE.rescue(text, 'song')` and the rest loads. Either way Ivan gets one toast pointing to **Settings › Backup › Rescued data**, where each copy can be saved as a `.txt` file (`rescueSave`) or deleted (`rescueDel`, with confirmation). A copy is made once per launch (`rescuing`), so pull to refresh doesn't make another.
- **Saving waits for a copy** (`holdSaves(promise)`): while a safety copy is being written, `save()` only remembers that it was asked, and saves once every hold has settled. The rescue and the pre-upgrade copy both hold saves, so the copy always exists before anything is saved over what it copies.
- **Saving can be switched off for a launch** (`lockSaves(why)`, `SAVE_LOCK`): when the damaged data can't be copied anywhere (`'uncopied'`), localStorage can't be read (`'unreadable'`), or reading or upgrading the data threw at launch (`'boot'`). The stored data is then left exactly as it was, and a toast says changes won't be saved this time. Drafts still save.
- **One IndexedDB helper** (`IDB.define(name, version, stores)` → `{open, tx, each, close}`): every database goes through it (`TAKES_DB`, `SAFE_DB`, and `CDB`, `TDB`, `XDB` inside coach.js, track.js and takes.js). `tx(stores, mode, fn)` settles on complete, error or abort (aborting itself if `fn` throws), so a save never hangs without a word when storage is full. After a failure the connection is dropped, and the next call opens a fresh one; a connection the browser closed is reopened once. An open that stays blocked gives up after 4 s. `each(store, fn)` reads every entry and never rejects. `define()` creates a store only when it's missing, and the names, versions and stores are the ones listed above.
- **Recordings that can't be read** aren't the same as none: `allTakes()` gives `null`, `refreshTakes()` keeps the list as it was, `TAKES_READ` stays false so `TAKE`'s tidy-up doesn't forget waveforms, an export fails with its toast rather than leaving the recordings out, and a restore stops before replacing recordings it couldn't copy.
- **A take that fails to save** (`saveRec`): it's kept in `UNSAVED` (`{t, r, xs}`, the take with its blob, the recording, and which practice it was recorded in) and a toast offers **Retry** (`toastBtn`). Retry, the app coming back to the screen and the next take that saves all try again (`retryUnsaved`); a take saved later joins its practice only if that practice is still the one running (`X.start === xs`). The song practice it started carries on.
- **`saveDraft()`** warns when it fails, at most every 10 seconds.
- **Startup** (`boot.js`): each step runs through `bootStep()`, which records what went wrong in `BOOT_ERRORS`. If the first draw fails, `#app` shows a short message with Try again; the launch screen goes whatever happens (`bootFinish`, and a last-resort timer), and a toast says something went wrong.
- **Longer toasts** use `toast(text, ms, 'long')`, which wraps onto a second line; `toastBtn(text, label, fn, ms)` adds one button in the style of Song Clock's Undo toasts.

### Data version

Saved data carries `schema` (currently 4, from 3.27; 3 was 3.18, 2 was 3.8, 1 was 3.7). Step 4 moves the older Annotate marks into the layered `marks` (see Marks); in practice it finds nothing to do, since `cleanData()` runs before `upgradeData()` and `cleanSection()` has already moved every section across (Q15 checked this; the step stays as a safety net, and numbered steps are never removed). Step 3 changes nothing: it marks data that may hold song timing. **A new optional field doesn't need a step or a new schema** (see Rules that keep old data working): raise `SCHEMA` only when a field's meaning changes. To change the shape of saved data:

1. Add a numbered step to `UPGRADES` that changes `D` in place, and raise `SCHEMA` to match.
2. Steps run in order the first time the new version opens, and whenever an older backup is restored. Before they run, the data is copied to the safety copies (`SAFE`, key `vocalBeforeUpgrade`, in IndexedDB since 3.29), and saving waits until the copy is there.
3. Add a test in `tests/test_data.py` that loads data from before the step and checks the result.

A backup whose `schema` is higher than the app's shows "Made by a newer version" before restoring.

### Songs

Each song in `D.songs` is its own record. Songs from before 3.8 have only `id` and `name`; everything else is optional.

| Field | Holds |
|---|---|
| `id`, `name` | Never change. Recordings (`songId`) and song practice (`songId`, `songName`) point at them. `name` is the title |
| `artist`, `pinned`, `added` | Artist (may be empty), pinned on Today and at the top of Songs (at most 3), when it was added (ms) |
| `practised` | When a take of it was last recorded (ms), set when a take is saved |
| `original` | The lyrics exactly as pasted. Never edited, so damaged lyrics can be rebuilt from it |
| `sections` | `{sid: {label, cue, lines, marks, held, ann, orphans}}`. `lines` is an array of lines, each an array of words. `marks` and `held` are the layered marks (3.27, see Marks below). `ann` and `orphans` are the same marks in the shape 3.26 read (`ann` maps `"line:word"` to `br`, `run`, `up`, `dn`, `v`, `nt`, `check`, `was`; `orphans` are marks whose word was removed), kept so a backup still opens in 3.26. This version only reads `marks` |
| `timing` | Song Clock (3.18), optional; none means not synced. `{len, est, slots: {o: {lines: [[start, end\|null], …], anch, marks: [line…]}}}` in seconds. See Song Clock below |
| `track` | Track player (3.19), optional: `{name, dur}`, the track's file name and length in seconds, so a song restored without its audio knows it had one. The audio itself is in `vocalTracks` |
| `loop` | The song's last loop (3.19), optional: `{start, end, on}` in seconds. Kept even without the track (like `timing`) |
| `ext` | The song's own optional extras (Q37), checked by `cleanSong()`, which keeps fields it doesn't know: `ladder` (`true` when Application's card sings the song as a ladder; absent is Straight) and (Q39) `key` (`{tonic, mode}`: the song's key, one of the 24 as the key sheet spells them, `mode` `major` or `minor`; absent is not set; checked by `SONGKEY.clean()`) | 
| `order` | The running order `[{o, sid}]`. Linked repeats share a `sid`; each `o` is one place in the song, and takes recorded from a section carry it. Unlinking and moving sections never change an `o` |

`cleanSong()` checks each song on its own when data loads or a backup is read: bad values are dropped, marks on missing words and order entries for missing sections are removed, fields it doesn't know are kept, and if the lyrics are unusable but `original` is there, they're rebuilt from it. Practised dates come from recordings (`TAKES`) and `practised`, whichever is later.

### Recall

Recall is a song mode (`U.sMode = 'recall'`) that hides lyrics without changing the layout: `maskText()` wraps hidden letters in `.hx` spans (`aria-hidden`), which are transparent with a rounded pill drawn by `.hx::after`, so every word keeps its width. `U.sHint` is the level (0 Full lyrics to 4 Blank) and `U.sOrder` is `start` or `end`. Neither is saved, and entering Recall always resets them. Tapping a `.rl` line adds `.peeking` for `peekSecs()` (only one line at a time); holding one for `HOLD_MS` adds `.peeking.held` until the pointer lifts. Neither re-renders.

**Labels above words (3.17; every layer's since 3.27):** a word with a label is `.w.hv`, holding the label `.v` (a centred `display: table` block) above the word's own text `.wt`. The word's inline-block is as wide as the wider of the two and its baseline is the word's, so labels push their neighbours apart instead of overlapping, and only lines (or wrapped parts of lines) with a label get taller. Nothing is absolutely positioned any more. A run's wavy underline is on `.wt` for labelled words, so it never runs under the label. test_lyrics' `singas()` checks no label overlaps a lyric, a mark or another label at four sizes, in Practise, Recall and Perform.

The only Recall setting is **Peek length**, `D.prefs.peek` (1, 2, 3 or 5 seconds; missing means 2). `D.prefs` holds settings that travel with backups; `cleanData()` drops values it doesn't know.

### Motion

Everything that moves uses `MOTION` (`js/motion.js`), so the app feels the same everywhere and later features never add their own easing. Since Q41 the springs, the speed and Reduce Motion are the parts kit's (`Parts.motion`, D18; see Parts kit below): `MOTION` reads them from the kit and keeps the app's helpers.

- **Springs:** `gentle` (ζ 0.82, 1.9 Hz: rows, capsules, sheets, fades), `nav` (ζ 0.86, 2.2 Hz: moving between pages, a little quicker) `ripple` (ζ 0.6, 2.4 Hz: peeks and small pops), `press` (ζ 0.75, 4 Hz) and `release` (ζ 0.55, 3.6 Hz) for the glass press (see Glass below), and the kit's own (`snap`, `bloom`, `settle`, `pill`, `sheet`, `menu-open`, `menu-close`). The kit publishes them; CSS uses `var(--dur-gentle)` and `var(--ease-gentle)` (and so on); JS uses `MOTION.animate(el, frames, {spring, delay, ms, fade})`, which does nothing (or a short fade with `fade: true`) when motion is off. An app spring that differs from the kit's is a line in `js/parts.settings.js` with its decision ID (none today).
- **Named easings (3.51, Q40):** `MOTION.EASE` (`pop`, `knob`, `out`) holds the same curves as app.css's `--ease-pop`, `--ease-knob` and `--ease-out`, for a fixed-length move that isn't a spring; `MOTION.animate` with `ms` defaults to `EASE.out`. Don't write a new `cubic-bezier(` in code (see Value set below).
- **Stagger:** `MOTION.stagger(i, 'word' | 'row' | 'bar')` gives 30, 45 or 30 ms per item, for `MOTION.animate`'s `delay` (which applies the speed, so the stagger itself doesn't, since 3.13).
- **Reduce Motion** (the iOS setting, or forced On or Off in Settings › Accessibility since 3.21: localStorage `vocalReduce`, `'on'`/`'off'`, absent = Match iPhone) and **speed:** the kit's (`Parts.motion.setReduced()`, `setSpeed()`); the app saves both on this device and hands them to the kit at start-up. `MOTION.reduced()` and `MOTION.on()` read the kit; `MOTION.on()` is false with Reduce Motion or speed 0. `MOTION.setSpeed(4)` is slow motion for tuning on a device, `setSpeed(1)` puts it back; it's kept in localStorage `vocalMotion`, never in backups. With motion off, every spring's `--dur-*` is `0ms` and `<html>` has `motion-off` (the kit writes both).
- **Distance blur:** `MOTION.blur(d)` (up to `BLUR_MAX`, 1.5 px, and 0 with Reduce Motion), `MOTION.dim(d)` (down to 0.3) and `MOTION.dimLabel(d)` (labels only dim, down to 0.45), where `d` is how many lines away from the focus. Song Clock's Blur ahead should reuse these.
- **Tests run with motion off:** the harness sets `vocalMotion` to `0` before each page loads. A test that needs real motion passes its own `init` setting it to `1` (see `test_lyrics.py`).
- **The launch ripple (3.13, `js/launch.js`, `LAUNCH`):** the app's signature moment. On a cold launch the icon's six sound-wave bars pulse in turn (`BAR`: 520 ms each, 70 ms apart, from 120 ms), the launch screen fades with a slight zoom (`FADE`: 300 ms, at 860 ms), then Today's blocks rise in, top to bottom, on `gentle` 45 ms apart (`RISE`). `boot.js` calls `LAUNCH.start()` before the first draw and `LAUNCH.finish()` once recordings have loaded and `LAUNCH.minWait()` has passed (at most `LAUNCH.capWait()`). `restoreImport()` calls `LAUNCH.replay(then)` to replay it on Today, with the toast in `then`. Tab switches and coming back to the app never replay it; an update reload is a cold launch, so it plays.
  - **Where the bars live:** `#splash` in `index.html` is the icon's plain background (an inline WebP, `<img>`) inside `.sp-icon`, with the six bars as `<i>` elements placed over it. Their positions, sizes, colours and shadow were measured from `splash/logo.png` so the icon looks the same at rest as the real one; `css/app.css` (`#splash i`) has their width and shadow. ### Recordings

Each take in IndexedDB is `{id, songId, created, len, size, type, star, blob, note?, o?, ext?}`. `ext.rung` (Q37) is the song ladder's rung a take was sung as (`trill`, `hum`, `vowels`, `words`: `RUNGS` in config.js); a take with a rung this version doesn't know is an ordinary take (`takeRung()`). `o` is the place in the song it was recorded from (an `order` entry); takes without one (song practice, and everything before 3.9) belong to the whole song. **Since 3.20 every take is kept:** the keep rule (`prune()`, `KEEP_TAKES`) is gone, and nothing removes takes automatically. Recording a section uses the same `startRec`/`stopRec`/`saveRec` as song practice, with a `{songId, o}` target; while it runs, `rec.o` locks the song screen to it. **A section take starts (or carries on) song practice for that song** (`rec.sp`): `X` is made with `newSong()` if there's none, timed from the take (`X.start = rec.started`), and the take joins `X.takes`.

- **Mono (3.20):** `monoStream()` (session.js) mixes the microphone down to one channel through a `MediaStreamDestination` (`channelCount 1`, explicit) before `MediaRecorder`, unless the track already has one channel; if the context won't run within 400 ms it records the microphone as it is, so a take is never lost to it.
- **The shared audio service (3.37, Q16):** `js/audio.js`, `AUDIO`. One AudioContext (`AUDIO.ctx()`, made once; `AUDIO.state().made` counts them) for everything that listens to the microphone. `startRec()` calls `AUDIO.wake()` first thing, inside the tap (iOS only starts a context from one), then `AUDIO.listen(stream)` once per take (`rec.mic`): one `MediaStreamSource` with `mono()` (the one-channel `MediaStreamDestination` for `MediaRecorder`, via `monoStream(stream, mic)`) and `analyser(n)` (the meter, later the analysers). `stopRec()` calls `rec.mic.close()`, which disconnects them; with nothing listening the context is suspended (never closed) and the next tap wakes it; 3.37.1: if it's still waking up then (the microphone refused straight after the tap, `AUDIO.state().waking`), it's suspended once it has woken. **It only hears the microphone:** the track, takes and the coach video stay on their own elements (track.js says why). Anything that needs it running must still work without it: `monoStream()` falls back to the microphone as it is, so a take is never lost. Analysers go here: `rec.mic.analyser()`, read on the frame clock. The pitch listener's live line (Q37) does exactly this (`APPL.liveLine()` → `PITCH.live()`); the vocal-weight analyser would too.
- **One frame clock (Q16):** `AUDIO.frame(fn)` calls `fn(time)` from one `requestAnimationFrame` for every subscriber and returns the function that unsubscribes; it stops when nobody's left. Anything drawn from the microphone uses it, and **looks nothing up on the page per frame**: keep the elements found after a draw and look again only when they're no longer connected. The level meter (`recMeter()`) does this: a new level about every 90 ms (`rec.lvAt`), its 14 bars found once per redraw.
- **Recording over the track (3.37, Q16):** the one exception to one sound at a time (Ivan, 30 Oct 2026). When the track player's sound is playing (`NOW.kind() === 'track'` and not play-along), `startRec(target)` doesn't stop it: it asks first (`askOver()`, sheet `recOver`, `recOverSheet()`): **Record with headphones** or **Record through the speaker** (Ivan, 31 Oct 2026: voice processing is off, so through the speaker the track leaks into the take; headphones by default, the speaker only after this confirmation; the app can't tell whether headphones are in). Both call `startRec(target, 'hp' | 'spk')`, which starts the recording with `NOW.start('rec', null, stop, 'track')`, so the track carries on under it (`rec.over`). Saying headphones is remembered in `REC_OVER.hp` only while the track keeps playing: it's forgotten on the track's next `pause` (iOS pauses it when headphones come out), on `devicechange` and when the app is hidden. The speaker is never remembered. Play-along, takes and the coach video still stop for a recording. On a song page the floating window still hides while recording, so the track's window comes back when the take stops. In Application (Q20) it's the red track window instead, and the track stops with the take (see Application). **Not yet checked on an iPhone (1 Nov 2026):** opening the microphone while the track plays can change iOS's audio route (the track quieter, or in the earpiece), and a locked phone suspends the context; recording already stops when the app is hidden, and the next tap wakes the context.
- **Names and comments** live with the song, not the take: `sg.takeNotes = {<take id>: {name?, comments?: [{t, text}]}}`, checked by `cleanTakeNotes()` (takes.js) from `cleanSong()`, so they're in every backup, even with Exclude recordings. Plain strings, for Search's Takes group (Render 10). Deleting a take (`TAKE.del()`) removes its entry.
- **On the device only** (`vocalTakeExtras`, stores `peaks` and `mono`, keyed by take id): `TAKE.analyse(id)` decodes a take once (22.05 kHz) into 50 peaks a second and measures each channel. If one is near-silent (under 3% of the other's RMS) it writes the live channel as a 16-bit mono WAV (`mono`), and `playTake()` plays that (`TAKE.blobFor(t)`) through the same `<audio>` path, so one sound at a time, the window, the lock screen and the silent switch behave as before. **The original recording is never rewritten.** New takes are analysed when saved; older ones in the background after launch (`backlog()`, one at a time), which also tidies extras for takes that have gone.
- **The takes sheet** (`sgTakes`, `TAKE.sheet(sd)`): `sd = {k, o?, all?, fresh?}`. With `o`, a segmented switch (`tkTab`) between the section and All takes; from the header's **Takes · n** button (`TAKE.headBtn(sg)`, beside the title, `tkOpenAll`) it opens on All takes. Rows newest first; tap (`tkTap`) expands one and plays it. The expanded take (`openId`) has the name (`tkRename`, inline), star, collapse, the comment pop-up strip (`#tkPop`), a canvas waveform (`#tkWave`, `data-own-gesture`, follows the finger), dots, times, −5 / play / +5 (`tkSkip`, clamped) and the comment field. Nothing is redrawn while a take plays: `TAKE.frame(player)` (from `playTake()`'s loop) and `TAKE.paint()` update in place. A take that ended plays again from 0:00.
- **Comments:** the first character typed locks the playhead time (`draft.t`); the chip (`#tkStamp`) opens −1 s · +1 s · Use current time; clearing the field lets go. Enter or Post saves `{t, text}` (≤ 200 characters), sorted. While playing, a comment pops up for about 2 s when playback crosses it (`prevT < t ≤ now`, and only within 0.6 s steps, so scrubs and jumps never do). Hold a comment: Edit · Delete (`sgCmtMenu`).
- **All takes as fold-out rows (3.26, Q10):** on All takes, when the takes come from two or more sections, `groupsFor()` makes a row per section in song order (`.tkfh`, `tkFold`, with its count and a chevron that turns down), with takes from no section last as Other takes. `folds` (a Set of `o`) holds which are open; it's set when the sheet opens (the expanded take's section, else the section the sheet came from, else none) and cleared when it closes. An expanded take's section is always open; shutting a section collapses its expanded take. Opening one turns the chevron and ripples its takes in (`gentle`, rows 45 ms apart); shutting fades them out quickly first. Takes inside sit on `--bg3`. A section's own tab, and All takes from a single section, stay plain lists.
- **Swipes and hold:** collapsed rows only. A sideways move claims the row (vertical scrolls the sheet; the sheet's own drag is only on its header). Right shows only Star (orange), left only Delete (red): a short swipe leaves the 84 px button, past half the row it acts (Delete always confirms, `sgTakeDel`). Hold 500 ms: Star · Rename · Delete (`sgTakeMenu`). The tap that ends a hold is swallowed, so it never lands on the menu that opened.
- **Review old takes** (`sgReview`, from Settings › Storage): unstarred takes with no comments, oldest first, each with a delete that confirms.

### The floating window

Since 3.12, `js/window.js` shows a small window on every screen outside the thing it's for. It's its own element, `#fw`, added to `<body>` and kept across redraws; **it must never go in `#layer`**, or the sheet scroll guards (`overlayOpen()` in gestures.js) would treat it as an open sheet.

- **One sound at a time (3.20):** every sound starts through `NOW.start(kind, id, stop)`: takes (`playTake()`, `nowTake()`), recording (`startRec()`, kind `rec`), the coach video (`COACH.play()`, or its `play` event when it's in `#app`), the track (`TRACK.play()`, also from song rows) and play-along (`ckPlay()`). Starting one calls the last one's `stop` and marks its window closed (`FW.dis`). `NOW.stop()` stops whatever plays (recording uses it); `NOW.ended(kind)` when a sound ends or stops itself. The lock screen's play and pause follow `NOW.last()`. There are no pairwise pauses any more: anything new that makes sound must start through `NOW`. **Q16, the one exception:** `NOW.start(kind, id, stop, over)` keeps the current sound playing under the new one when it's of kind `over`; only `startRec()` uses it, with `'track'`. The track is then `under` (`NOW.under()`): `NOW.kind()` is `rec`, the track starting again (the lock screen's play) stays under the recording, `NOW.ended('rec')` makes the track the current sound again (and `NOW.last()`), and anything else starting, or `NOW.stop()`, stops both.
- **✕ and closed windows (3.20):** every sound kind has `close()` and the default window draws a ✕ (`fwX` → `fwClose()`); the video's own draw has it too, playing or paused. `FW.dis[kind]` keeps a kind out of `fwPick()` until its next `NOW.start()` (an explicit play); nothing else clears it: tab switches, redraws, sheets, `fwUpdate()`, the app coming back or a reload. `FW.shut` (set by ✕) keeps every kind, sessions included, off the current screen; `go()` clears it. A sound paused anywhere but the window or the lock screen (`FW.winAt`, set by `fwToggle` and the lock screen handlers) is closed too (`fwPaused(kind)`), so the window shows a sound while it plays and when paused from the window. A sound that ends leaves (each `active()` is false once ended). The session kind has no ✕ and its own screen now includes the song page of the song it practises.
- **Kinds:** `FW_KINDS` lists what can be shown, in the order they win (since 3.19: take → video → track → clock → session): `take` (a take playing or paused from the window), then (Q19) `coachpill`, the session page's Coach pill (no ✕: tapping it shows the video), then `session` (a session with a `start`; untimed song practice has none; since Q22 it has its own `draw()`: the session clock's ring, small (`SCLOCK.mini()`), beside "Rotation · 4:16" in the step's colour, and its pause button). ### Song Clock

Since 3.18, `js/clock.js` times a song's lyrics. **Timing says when; marks say how:** timing is its own layer on the song (`sg.timing`) and never changes the lyrics, sections, marks or takes. Built so far: phase A1 (play-along, Check timing, the header and grid), Q02 (section starts set on the track's waveform, play-along from the track: see The track player) and **Q05 (3.28, Song Clock: Tap Re-Anchor): timing runs off the song's own track on this device.** Lines are placed on the track's waveform (the line lane), fixed while playing along (punch-in), flagged with a track marker, and reached from a hold menu on any lyric line. Sync by sections (tapping along to music on another device) and play-along without a track are retired; Q06 was folded into Q05. Q07 (paced Recall, now a Not scheduled idea) would build on it.

- **No timing without a track (Q05):** `ckCan(sg)` is `TRACK.has(sg.id)`. Without it the Timing tile and pinned icon read **Add a track to time this song** and open the track picker (`ckAskTrack()`, the song's Track row's door); `ckOn()`, `ckPlay()` and `CLOCK.after()` refuse or turn play-along off. Timing saved on an older song (or with its track on another device) is kept untouched and shows on Check timing, with a note that play-along needs the track (Ivan, 30 Oct 2026). Timing on an untimed song with its track goes straight to the track player (`ckRetime(sg, 0)`).

- **Data:** `timing = {len, est, slots}`. Times belong to **places in the running order** (`o`), not sections, since Chorus 2 is sung at a different time from Chorus 1 (marks are the opposite: once per section). Each slot has one `[start, end]` per line of its section (`end` may be `null`), `anch` (the section's start is set: from a marker made a section start, or a section's first line placed by hand) and `marks` (to-do markers, line numbers). Q05 adds two optional lists of line numbers (older versions drop them, harmlessly): `fix`, lines placed by hand on an estimated song, and `sb`, **suggested breaths** (see below). `len` is the song's length (whole seconds, up to 20:59). `est`: lines were spread evenly from section starts; a line stays estimated until it's in `fix`, and the song stops being `est` once every line is (then `fix` is dropped). **Q12:** moving a timed section (`ckMoved(sg, o)`, from `sgEndDrag`) uses the same fields: the song becomes `est` with every other placed line in `fix`, so only the moved place's lines are estimates (its start kept), with no new field. **Q17:** `real` (the clock matched the music app's song time) was never used and nothing writes it since 3.38; it stays in `CK_T_KNOWN` so older saved timing that has it still loads, and `cleanTiming()` drops it (kept as an unknown field, it would stop empty timing being dropped). The schema stays 4. **Q15:** fields this version doesn't know are kept at every level, as they are: on the timing (`CK_T_KNOWN` are the known ones), on each slot (`CK_S_KNOWN`), and on each line, whose items after its start and end are kept (`ckLineExtra()`). New ones go in `timing.ext`, `slot.ext` and a line's third item, `[start, end, ext]`. `cleanTiming()` and `ckStore()` both keep them (ckStore takes them from the timing it replaces, line by line by place `o` and line number); a lyric edit keeps a line's along with its time. Timing with only extra fields isn't dropped (`ckEmpty()`), and clearing the length keeps it.
- **Checking:** `cleanTiming(t, sg)`, called from `cleanSong()`. It drops slots for places no longer in the order, extra lines, junk, bad markers and set starts, and any line that starts less than 0.1 s after the one before (an end that overlaps the next start is trimmed). `fix` and `sb` are checked like `marks` (in range, no repeats, sorted); a suggested breath also needs its line timed and goes once the line has a breath mark of Ivan's. Nothing in it can break the song.
- **The maths** (all in clock.js): `ckLines(sg)` lists every line in running order with its syllables (vowel groups) and whether it has a breath mark of Ivan's. `ckRaw()` reads the saved times; `ckFill()` gives every line a time to play from (lines without one are spread between their neighbours; Q12: with no room, as between two touching lines, they're squeezed between the two starts so neither moves) and `ckOrder(T, placed)` keeps the estimates in order (each starts ≥ 0.1 s after the last, the last one's end is trimmed, and every line lasts ≥ 0.1 s). **Q12: `ckOrder` never rewrites a placed line** (the `placed` mask); placed lines out of order stay as they are and `ckOverlaps(M)` flags them on Check timing (**Overlaps**). Without a mask everything counts as an estimate. `ckEnd()`: a missing end is the next line's start or 0.3 s a syllable, at least 1.2 s. `ckSpread()` spreads each section's lines by syllables between set section starts. Q12: every section before a set start fits in before it (ending a second early): at their natural pace if they fit (the last stretched to fill), else squeezed together; with no room at all (under 0.2 s a line) they're left without times, as estimates. A set start's first line is never pushed. `ckWarp()` stretches piecewise-linearly through set points (a plain shift outside them). `ckModel(sg)` bundles all of it, with (Q05) `est[i]` (estimated: no time of its own, or spread and not placed) and `sb[i]`, and (Q12) `placed[i]` (a time Ivan set: a line placed by hand, or a set section start's first line) and `anch[k]`, which only counts while the section's first line has a time. **Writers read `M.raw` with `M.placed`/`M.est`, never the filled `M.T`** (that's for play-along and drawing). `ckBounds(M, i)` is the starts of the nearest placed lines either side: the only limits for punch-in, Start here / End here and lane drags (none if those lines are out of order). Presses have `CK_LAG` (0.15 s) taken off.
- **Writing:** `ckStore(sg, L, T, anch, marks, flags, fix)` writes every line, keeps `fix` as it was unless given, clears `est` once every line is placed, and works out `sb` from scratch: a gap of at least `CK_SB` (0.25 s) between a placed line's end and the next placed line's start, on a line with no breath mark of Ivan's. **`ckSetLines(sg, {i: [start, end]})`** is the one door for fixing lines in place (the line lane, Start here / End here, punch-in): `ckSnap`, the saved times with the changes, the lines become placed, lose their to-do marker, a section's first line sets its start; the placed line before ends by the new start and the line's own end comes by the next placed start (Q12: only next to what changed); then `ckStore` and a "Re-timed “…”" toast with Undo. It refreshes whatever shows the timing (`TRACK.refresh()` in the player, else a redraw or `CLOCK.after()`).
- **Retime** (`ckRetime(sg, i)` → `TRACK.retime(id, i, t)`): the track player in Line view, the playhead on line i's start and its block selected, pushed in from a song page or Check timing (`ZOOM.armPush('trk:retime')`); Back returns there (`TRACK.back()` remembers Check timing). Its doors: every Check timing line row, its Section starts row and Time each line (the first estimated line), the hold menu's Retime line, play-along's Retime (paused) and Timing on an untimed song.
- **Sync by sections is retired (Q05):** its screen (`ckSync`), pad, clock (`CK.sc`, `CK.P`) and the Sync again tile are gone; a pinned `sync` is dropped by `ckPrefs()`. `ckSpread()` stays (a marker promoted on an untimed song spreads the lines).
- **Play-along:** `CK.on` for `CK.songId`, clock `CK.pc`. The big view is its own fixed layer, `#ckpa` on `<body>`, placed over the song's column below the header row (so Timing and ⋯ stay in reach); the page goes to the top and can't scroll while it shows (`html.ckplay`). Pausing hides the layer, so the real lyrics page is underneath, with the current line `.sgl.ckcur` scrolled to where the layer's line was. `ckTick()` (every frame while a clock runs) sets past/now/future, the word fill (`--p` on `.ckw`, by syllables), Blur ahead (`MOTION.blur`, `MOTION.dim`, `MOTION.dimLabel`), the automatic dots and the transport's time (text only: digits never animate). The view is rebuilt only when the song or the settings change (`ckSig`, which since Q14 leaves the timing out; `CK.drawn` is what the lines were built from). The transport capsule (`.cktr`) is in `#dock`, so `fwBounds()` already avoids it. (3.22's search circle sits only beside the tab bar, so it isn't on this screen.)
- **Per-frame work (3.34, Q14, Playback: Smooth Frames):** nothing looks different; each frame just does less.
  - **The kept model:** `ckModelK(sg)` is `ckModel(sg)` kept in `CK.mdl` between frames (as track.js keeps `mdl`), for the readers that run every frame: `ckTick()`, its marking-while-listening highlight and `ckFwText()`. It's dropped by every `CLOCK.after()` (so every redraw) and by `ckStore()`, and rebuilt if the song's `timing`, `order` or `sections` object is replaced. **Writers never use it:** they keep calling `ckModel()` and reading `M.raw` (Q12). If you change a song's timing in place without `ckStore` or a redraw, set `CK.mdl = null`.
  - **The lines, once per build:** `ckDom(el)` finds the big view's lines, words, dots and labels once (`CK.dom`, dropped when `CLOCK.after()` builds the view again) and remembers what was last written to each line (`st`: class, `nx`, opacity, filter, word fill; `wp`: each word's `--p`), so a frame writes only what changed. `CK.lastA = -2` still forces a full pass; it now writes only the differences.
  - **Reads before writes:** on a line change `ckTick()` reads the view's height and every line's `offsetTop`/`offsetHeight` first, then writes. Classes, fades and blur never change a line's size (Active layer's marks are `visibility: hidden`, not removed), which is what makes this safe: keep it that way.
  - **Blur on screen only:** a line gets its Blur ahead only while it's within a screen of the view, at the view's old or new place (`seen`), so lines passing during a jump are blurred too; the rest have no filter. Opacity still goes on every line.
  - **Only the timing changed** (a punch-in, a nudge, Undo): `CLOCK.after()` keeps the lines and calls `ckDots(sg)`, which adds or removes each line's automatic dot (`ckDotAt()`, the same rule `ckBuild()` uses) and redraws them without easing (`nofx`), as a new build would. Anything else in `ckSig` changing still rebuilds.
  - **A line tap** in the big view (`ckPlay(i)` while the view is up) calls `renderDock()`, `CLOCK.after()` and `fwUpdate()` instead of a full `rerender()`.
  - Tests: `tests/test_frames.py`.
- **Marks while playing** (`vocalSongPrefs.marksPlaying`): `'off'`, `'breaths'` (default) or `'active'` (3.27), cycled in that order by the tile. Breaths only shows Ivan's breath marks (`.ckbr`) and an automatic dot (`.ckdot`) only on a line with a gap over 1.2 s after it and no breath mark of his. **Active layer** also draws the chosen layer's marks on every line (`ckBuild()` through `MARKS.line()`), but `#ckpa.mpact` hides them except on the line being sung (`.now`) and the next (`.nx`, set by `ckTick()`), so line heights never change while playing. - **The header and grid:** `ckHeadHTML()` (artist · length, pinned icons from `pins`, ⋯), `ckGridSheet()` (sheet `ckGrid`), `ckTileAct()`. ### The track player

Since 3.19, `js/track.js` plays a song's real track for drilling: import it from Files, see its waveform, zoom, scrub and loop a phrase slowly with the pitch kept. The repo is public: **never commit real music.** Tests write synthetic WAV files (tones with gaps) into `tests/output/`.

- **Data:** `sg.track = {name, dur}` and `sg.loop = {start, end, on}` live in the song (backed up). `cleanSong()` checks them; `cleanLoop(l, dur)` (track.js) needs numbers ≥ 0, clamps the end to the track's length and drops a loop shorter than `TRK_MIN` (0.5 s). Q15: `cleanLoop()` and `cleanMarkers()` keep fields they don't know (new ones in `loop.ext` and `marker.ext`), and `setLoop()` keeps the loop's when it sets a new range. `sg.track` is still rebuilt as `{name, dur}`. The schema stays 3: the fields are optional and older versions keep fields they don't know. The audio and its peaks are separate entries in IndexedDB `vocalTracks` (stores `audio`, `peaks`, keyed by song id). `TRACK.load()` (boot.js) lists which songs have one (`have`).
- **Importing** (`add()`): `<input id="trackIn">` with each format named in `accept` (3.19.1: iOS greys out audio files in Files for `audio/*`), opened by `TRACK.pick(id)` (or `pick('draft')` for the + sheet's Add media, 3.20: the file is read with `TRACK.read()` and kept on the draft; `TRACK.attach(sg, file, r)` stores it only on Save). Over `TRK_BIG` (60 MB) it asks first (sheet `trkBig`). The file is decoded **once** with an `OfflineAudioContext` at 8 kHz (falling back to 22.05/44.1 kHz if refused) and reduced to 50 peaks a second (`Uint8Array`, scaled to the loudest). A file that won't decode says `TRK_BAD`. Replacing keeps the loop (trimmed to the new length) and timings; a length more than 1 s different shows `TRK_LENGTH`. **Q12, a shorter track:** `attach()` takes `ckSnap(sg, true)` first (Undo puts the timing, markers and loop back) and counts markers past the new end (start or end) and lines starting at or after it (`ckPast()`). If there are any, `past` is set and sheet `trkPast` asks: **Trim to the new track** (`trkPastTrim`: `cleanMarkers` against the new length, and `ckTrim()`: those lines lose their time with a to-do marker, a first line takes its set start with it, nothing ends after the end) or **Keep them** (`trkPastKeep`, also what closing the sheet does). Both toast with Undo. `cleanSong()` no longer trims markers to the track's length, so kept ones survive a reload. Opening the player never decodes again (`open1()` reads the saved peaks; it decodes only if the peaks went missing, and saves them). **Q17:** `loading` stays set while missing peaks are read again, and `open1()` checks it once more afterwards, so a track asked for in the meantime (another song's) stays in the player; the peaks are still saved.
- **Playback:** one `<audio>` (not in the DOM), `playbackRate` with `preservesPitch` (and the webkit/moz names). Not `AudioBufferSourceNode`: its gapless loop would shift the pitch when slowed. The loop is checked every animation frame (`frame()`): when playback crosses the loop's end (`prevT < end ≤ t`), it seeks to the start; a small gap there is accepted. **Q09:** `armWrap()` (from each frame, `timeupdate`, `play` and `seeked`) sets a timer once the end is under `WRAP_SOON` (0.3 s of real time, at the current speed) away, so the jump back (`wrapTo()`) lands within a few ms of the end instead of up to a frame late (or a `timeupdate` late, locked); the frame and `timeupdate` checks stay as the safety net, so no boundary is missed. Still one `<audio>` with its pitch kept: a second element or Web Audio would fight the lock screen, one sound at a time or the pitch. `TRACK.wraps()` lists the last 30 wraps (`{t, start, end, rate, by}`) for the tests. Play with the loop on from outside it starts at its start. `seek()` sets `prevT`, so jumping past the end never counts as crossing it. **The join itself (audit M8, Q16):** the jump is a seek of the `<audio>`, which may leave a small gap on iPhone. Ivan's check of the join at 1× and 0.5× is pending (1 Nov 2026); if the gap is audible, a short fade at the join is the follow-up, not Web Audio looping.
- **The page** (`U.view = 'trk'`, `U.songId`): `TRACK.page()`, `TRACK.bar()` (Back, title, ⋯ for sheet `trkMenu`: Replace track…, Remove track → `trkDel`, Clear all markers, and (Q02) the jog wheel's side), `TRACK.dock()` (the transport `.trktr`: back to loop start, play, loop; in Markers (Q09) `.trkmd`, a row of pills `.trkmp` (Backing Sound `trkSnd`, Loop `trkMdLoop` with id `trkLoopB`, so `paint()` keeps it) over three pads `.trkpads`: Replay `trkReplay`, Play/Pause `trkPP`, Next `trkNext`, 95:140:95 px, shrinking in proportion when narrower; all in `#dock`, so `fwBounds()` already avoids it, and `main` gets more bottom room while `.trkmd` is shown). ### Marks

Since 3.27 (queue item Q03), marks come in four layers, one per stage of learning a song, plus a Note on every layer. Only one layer shows at a time. `js/marks.js` (`MARKS`) holds the data side and drawing; selecting words and the marks sheet are in songs.js.

- **The marks** (`MK_DEF`, `MK_BY`): **Notes** (Pitch, Slide, Hold, Ornament, Rhythm), **Phrasing** (Phrase, Chain, Peak, Breath, Shape), **Words** (Vowel, Carry, Onset, Stress, Say), **Delivery** (Register, Colour, Vibrato, Mic, Intention), and **Note**. Each has its options (`opts`), whether options take text (`txt`) or need it (`need`: Sing as…, Say, Intention), and where it lands in a selection (`at`, `mkAt()`): Peak, Onset, Colour and Register (except Flip here) on the first word; Phrase, Stress and Shape keep the range; Intention belongs to the section; the rest go on the last word.
- **Data:** each section's `marks` is `[{id, L, type, opt, line, w0, w1, text, check?, was?}]`, stored once per section, so every repeat of a linked chorus shows the same marks. `L` is the layer (`'note'` for Note) and must match the type. `line` is `-1` for Intention (one per section). `w0 ≤ w1` are word indices within the line. `text` is up to 80 characters (Notes 200). `held` is marks whose word was removed: `{id, L, type, opt, text, was}` with no place. `mkCleanSection()` (from `cleanSection()`) drops only bad marks (missing required text, out of range, a second Intention), puts a one-word mark given a range on its word, removes exact duplicates (marks that differ only in fields this version doesn't know are both kept, Q15), and keeps fields it doesn't know (new ones go in `ext`, see Rules that keep old data working).
- **Inactive marks (3.36, Q15):** a mark with a type or option this version doesn't know, or a layer that doesn't match its type (from a newer version), is **kept as it is but inactive**, in `marks` or `held`: only its place is checked (`mkCleanIdle()`: a mark on a missing word still goes). `mkActive(m)` (`MARKS.active`) says whether this version can use a mark and `mkLive(list)` (`MARKS.live`) gives the ones it can; **every reader goes through them**: drawing (`mkDeco`), the 3.26 copy (`mkMirror`), the pencil's count (`MARKS.checks`), On these words (`MARKS.onSel`), breaths for Song Clock, the lyrics editor's highlights, the Intention, the held list and Move on the Marks side, `sgChecks()` and Key for this song. So they never show, count or play along, and Search only searches words. `MARKS.add()` never replaces an inactive mark. Lyric edits move them with their words like any mark (`mkRelink`, not counted in its total). A new reader of `sec.marks` or `sec.held` must use `MARKS.live()`.
- **Extra fields survive editing (Q15):** `MARKS.add(sec, sel, type, opt, text, from)` gives the new mark the extra fields (`mkExtra()`, everything but `MK_KNOWN`) of `from` (moving a held mark: `selectWord()` passes it) or else of the mark of its type it replaces on those words (re-adding, changing an option). Undo still puts the replaced mark back as it was.
- **Moving the older marks across** (`mkMigrate()`, data step 4, and any section that arrives with `ann` and no `marks`, such as an old backup): `up`/`dn` → Notes · Pitch · Up/Down, `run` → Notes · Ornament · Run, `br` → Phrasing · Breath, `v` → Words · Vowel · Sing as… with its text, `nt` → Note with its text; `check`/`was` carry over to each; anything else on an old mark becomes a Note carrying its name and value. `orphans` become `held`.
- **The older copy** (`mkMirror()`): every change to a section's marks redoes `ann` and `orphans` in 3.26's shape (breaths, runs, pitch up/down, vowels with text, Notes), so a new backup still restores in 3.26 ("data changes are additive"). Anything that changes `marks` or `held` must call `MARKS.mirror(sec)` (`MARKS.add`, `MARKS.remove` and `relink()` do). Marks added in 3.26 after a 3.27 backup was restored there aren't read back: this version only reads `marks`.
- **Following their words** (`mkRelink()`, from `relink()`): each word is matched by `align()`; a mark moves with its word; a changed word moves it to the new word with `check` and `was`; a removed word sends it to `held`. A range keeps the words still there (on the first remaining word's line) and is flagged if any changed or went. Checks count towards the pencil's badge (`MARKS.checks()`).

### Rules that keep old data working

- **Never rename or remove an exercise id** (`slides`, `humming`, `lip`, `straw`, `falsetto`, `upperlower`, `rung`, `hinge`, `half`, `vertical`, `nasal`, `flex`). Sessions store levels by these ids. The backup tests fail if they change.
- **Data changes are additive.** Add fields with a default; don't rename or repurpose existing ones. Older backups must still restore, and new backups must still restore in the previous version.
- **Optional extras go in `ext` (3.36, Q15).** A new optional field on a record goes in that record's `ext` object: `mark.ext` (and a held mark's), `timing.ext`, `slot.ext`, a timed line's third item `[start, end, ext]`, `marker.ext`, `loop.ext`, `song.ext` (Q37: `ladder`; Q39: `key`), a take's `ext` (Q37: `rung`), a session's `ext` (Q20: `app`) (and `section.ext` if ever needed). The feature that adds a field checks its own fields there, so the record's checker stays simple. Every checker and writer keeps fields it doesn't know, in `ext` or not, as they are (`dataExtras(rec, known)` in storage.js lists them), so a backup made by the next version restores here and goes back out unchanged. When you add a known field to one of these records, add it to that record's known list (`MK_KNOWN`, `CK_T_KNOWN`, `CK_S_KNOWN`, `TRK_LOOP_KNOWN`, `TRK_MK_KNOWN`) and check it.
- **A new mark type or option needs no schema change:** the version before keeps it as an inactive mark (see Marks). A new register option, for example, goes in `MK_DEF.register.opts`, with its `GUIDE` words.
- **Raise `SCHEMA` only when a field's meaning changes.** Adding optional fields isn't that.
- `tests/test_extras.py` restores `tests/fixtures/backup-next.json`, a made-up backup shaped as the next version would write it (unknown marks, options and layers, `ext` and other extra fields at every level), checks nothing is lost, inactive marks stay invisible and editing keeps every extra field, and that it goes back out unchanged. When a version adds real fields, add them to that fixture's next copy rather than changing what's there.
- **Bump the IndexedDB version only to add stores**, and create each store only if it's missing. Every database opens through `IDB.define()` (storage.js, Q11); don't write another copy of the open and transaction code.

## Backups

A backup is a JSON file with: a plain-English `README` array, `app`, `format` (2), `appVersion`, `exportedAt`, `device`, `summary`, `data` (= `D`), `draft` (= `X`), `takes` (recordings as data URLs) and `checkCode`.

- **Exclude recordings** writes `takes: []` and `recordingsExcluded: true`, and the check code is worked out on that file as written. Check a backup and Import say "Recordings not included", and restoring one keeps the device's recordings (the undo copy notes `keptTakes`, and undoing leaves them alone).
- `checkCode` is the SHA-256 of `JSON.stringify({data, draft, takes})`. `inspectBackup()` recalculates it to decide whether a file is complete (`good`), from before 3.6 (`old`), edited or partly copied (`changed`), missing some recordings (`partial`) or unusable (`broken`).
- Export reads its own file back through `inspectBackup()` before offering to save it.
- Restore keeps an undo copy first; `undoRestore()` puts it back.
- Files are named `Vocal Sessions backup · YYYY-MM · Device.json`, so iOS offers to replace the month's file.

The fixtures in `tests/fixtures/` are real backups made by 3.5 and 3.6, plus a copy of the 3.6 app. **Don't regenerate them.** `backup-next.json` (Q15) is different: made up, shaped as the next version would write it (see Rules that keep old data working). They prove that old backups keep working, and that new backups still open in 3.6.

### The pattern player (3.48, Q32)

Every exercise page explains the exercise and plays it. The playing is one shared piece, `js/patterns.js` (`PAT`), so it can be reused elsewhere (a Today widget, say) and changed without touching the pages that use it.

- **What a page tells it** (`PAT.use(o)`, called while the page draws): `{key, name, col, route, def, syl, vowels, fal}`: where its choices are saved (the exercise id), its name and colour, the route (MIDI key notes, one per round; empty or `null` means no player), the default pattern, what's sung (for the vowel cue), whether it's sung on open vowels and whether its high notes are in falsetto. Then `PAT.card()` is the drawing card (on the page) and `PAT.dock()` the dock; `renderDock1()` shows the dock instead of the tab bar while `PAT.onPage()` (an exercise's Summary, pushed or in the iPad's split pane, which `PAT.after()` lines the dock up under) and nothing on the Patterns page.
- **The exercise page** (`exSummary()` in screens.js): `EX_PAGE` in content.js holds each exercise's steps, Where you feel it (a glow spot), syllables, default pattern, `vowels`/`fal`, its three levels (words, the coach's starting notes and a shift) and the facts with their icons (`FACT_ICON` in config.js). The level shown is the last logged (`exLogged()`), until a level dot is tapped (`U.exLv`, cleared by `openEx`). The fix tip is the last sentence of `DESC[id].why`; Why it helps shows its first sentence with More (`U.exMore`). Vocal slides has no notes, so `exSlides()` draws a still picture and the tab bar stays. Custom exercises keep the old page.
- **Routes:** each level's starting notes are copied from `tools/coach-video/data/audio_timeline.json` (consecutive repeats dropped), moved by the level's shift where the coach's pattern starts above its key (Humming 2: −4, Half squeaky 1: −7, Upper to lower: −7). Squeaky hinge's notes were never saved, so its route is made up. `test_patterns` › routes checks every level against the note data. The starting-note stepper moves the whole route (`ex[key].off`).
- **The library:** `LIB`, 60 patterns: number, name, group (`w` `a` `r` `x`), steps, semitones (`null` is a breath), family (riffs: `s` `t` `l` `m`), note lengths (`rh`; 1 = a beat, under 0.5 is a quick touch, played lighter and drawn smaller; the last note is always held 2.2 beats) and what it trains (shown on a press and hold, and as the tile's VoiceOver hint). Numbers are saved, so never renumber; add new patterns at the end. **Minor:** a pattern that uses ♭3 or ♭7 and never the major 3rd (`isMinor()`) gets minor round and home chords.
- **Sound** (Web Audio, no recordings): `SOUNDS`, one entry per sound (`{id, name, play(f, t, d, out, v)}`); adding a sound is adding an entry. Each round: the new key's chord (`cue`), then the pattern two beats later, with the key an octave down held underneath (`drone`, always Soft tone), then a two-beat gap. After the last round the home ending (`ending`: the chord, the note and its octave, or off) plays the first key. Stop fades the output (`newBus`) over about a third of a second. The player has its own AudioContext (the shared `AUDIO` only ever hears the microphone), made in a tap, with a looped silent WAV `<audio>` started in the same tap so the silent switch doesn't mute it (paused whenever the page is hidden) and `navigator.audioSession.type = 'playback'` where it exists.
- **One sound at a time:** everything starts through `NOW.start('pattern', …)`: playing (id: the exercise), a pattern previewed on the Patterns page (`'preview'`) and samples (`'sample'`: a sound picked, a starting note, an ending). Another sound starting stops it quietly; it calls `NOW.ended('pattern')` when it stops itself. It also stops when its page goes (`PAT.after()`) or the app is hidden. The screen stays awake while it plays (`AWAKE.set('pat', …)`).
- **Rounds:** `next()` schedules a whole round ahead on the audio clock and a timer starts the next one; `S.hold` (Stay on this key, not saved) repeats the key; `ramp` (Speed up each round) adds one speed stop a round up to 2×, without changing the saved speed. A speed changed while playing applies from the next round. `PAT.state().runs` lists the last 40 rounds for the tests.
- **Speed:** 12 stops (`SPEEDS`, 0.5×–2×; a beat is 0.36 s at 1×), saved per pattern (`spd[n]`, absent = 1×). The pill opens the slider on a tap, or on a hold so a drag carries straight on (pointer events on `#pSpd`); the slider (`#pHud`, on `<body>`, `data-own-gesture`) moves with the finger from the current speed, snaps to the stops, stretches past either end, lights the drawing's dots at the new tempo (no sound) and closes after 2.6 s.
- **The range check:** `rangeCheck()` against your voice (`voice`: tenor G♯2 · A4 · falsetto top D5 until set); `fal` exercises and any Flips pattern use the falsetto top. Out-of-range notes of the round shown are labelled in orange, and the range line (`#pcRange`, a door to Your voice) says where. Stop at my top note (`stopTop`) ends the route before the first round above the top.
- **The drawing** (`svg()`, `geom()`): held notes take more room, quick touches less, a breath breaks the line; dots or music notes (`notes`). `tick()` moves the red playhead and lights the dots on one frame loop for whichever drawing is live (`#pcDraw` playing, `#pwDraw` previewing), re-finding its elements after a redraw; ripples only with motion on. While playing nothing is redrawn: `paint()` and `paintDock()` update in place.
- **The Patterns page** (`U.view = 'pat'`, `PAT.page()`): opened from the pattern pill (`data-zk="pat"`) through `go()`, so it's the app's card zoom; `ZOOM`'s `cardEl()` also looks in `#dock` for it (Q32). Back (`patBack`, to `U.patFrom`) and swipe back shrink it into the pill. The group control and the window (`.pfix`) are sticky under the bar; only the tiles scroll. The window plays like the exercise drawing and never highlights itself. A tap on a tile picks and previews it; a press and hold (450 ms) adds `.held` (what it trains fades in) and a hold never picks (`holdEnd`).
- **Saved choices** (`D.prefs.pat`, in backups): `ex[key]` `{p, off}` (only when not the default), `spd`, `fav` (absent: the eight seeded riffs), `voice`, `sound`, `drone`, `cue`, `ending`, `vowel`, `notes`, `stopTop`, `ramp`. Nothing is saved until a choice changes. `PAT.clean()` (from `cleanData()`) drops only what's malformed and keeps fields it doesn't know.
- **From outside an exercise (Q39):** `PAT.guest({id, name, n, k, key})` opens the player for Practise in <key> (VS-097): `cfg.key` is `song:<id>`, `cfg.guest` is true, the route is the one starting note `k`, the pattern `n`, and Stay on this key on. Its pattern and starting note live in `cfg.gx` (memory only): `exPref()` and `putEx()` read and write there for a guest, so the Patterns page, the starting-note stepper and picks never touch `D.prefs.pat.ex`. Speed (per pattern), sound and the other player settings are the player's own, shared as everywhere. `onPage()` is true on `U.view === 'keyp'` with a guest; Patterns' Back returns there (`U.patFrom`). The next exercise page's `PAT.use()` replaces the guest. `PAT.hear(n, k, onEnd)` plays a pattern once from key note `k` through the preview (`NOW.start('pattern', 'preview')`), and `PAT.hearStop()` stops it; `preview(p, k, onEnd)` takes the same optional key and callback.
- **One note (Q37):** `PAT.tone(m, {repeat, onEnd})` plays one MIDI note in the chosen sound (1.1 s, a fresh output each strike) through `NOW.start('pattern', 'tone', …)`; with `repeat` it strikes again every 1.5 s until `PAT.toneStop()`, another sound starting or the app being hidden. `onEnd` is called once, however it stopped. `PAT.toneState()` is `{m, repeat, strikes}` or null. The song ladder's note buttons use it.
- **Settings:** Your voice (voice type as a pop-up menu, three steppers that make it Custom, Stop at my top note) and Pattern player (sound, Held note underneath, Chord before each round, Ending, Vowel cue, Notes on the drawing). `PAT.menu`'s pull-up menu (`.pmenu`) is also the sound pill's.
- **Bridge-aware (Q38):** the bridge band, ringed notes, softer notes, the cue, Stop one past last time and Listen while I sing are in this file too; see Bridge-aware patterns below.
- **Out of scope for Q32, left for later:** recording on this page (Exercise takes), Listen then sing, a breathing gap, custom patterns, playing in a session or with the coach video, Today widgets, note lengths and attacks.
- Tests: `tests/test_patterns.py` (see Tests).

### Value set (3.51, Q40)

One named set of look and motion values, beside the text sizes at the top of `css/app.css`, so the app stops drifting into one-off corners, presses and curves (Ivan's app look skill, 6b). It came from the consistency audit of 3.49 (26 corner sizes, 7 press shrinks, 56 hand-written curves, 31 durations).

- **Corners:** `--r-small` 10 (icon tiles, badges, small inner boxes, the focus ring), `--r-medium` 14 (fields, banners, inner boxes, menus), `--r-card` 20 (cards, grouped lists), `--r-large` 26 (big blocks, pads, the iPad hero), `--r-sheet` 34 (sheets, the session clock). Capsules stay `999px` and circles `50%`.
- **Press:** `--press` 0.93, for every solid button's `:active` shrink, written `transform: scale(var(--press))`. Glass buttons grow instead (`PRESS`, see Glass below).
- **Motion:** `--ease-pop` (`cubic-bezier(0.3, 1.7, 0.45, 1)`, the solid press settle), `--ease-knob` (`cubic-bezier(0.3, 1.35, 0.5, 1)`, the segmented knob's settle) and `--ease-out` (`cubic-bezier(0.2, 0.8, 0.2, 1)`, one settle without a bounce), beside MOTION's springs (`--ease-gentle`, `-nav`, `-ripple`, `-press`, `-release`, see Motion above). Code uses the same three as `MOTION.EASE.pop`, `.knob` and `.out` (`MOTION.animate` and the zoom's timed moves default to `.out`). Fades and colour changes: `--dur-quick` 120 ms and `--dur-fade` 200 ms. These two are fixed: unlike `--dur-gentle` they don't follow motion speed or turn to 0 with motion off.
- **Exempt:** graphic corners of 6 px and under (bars, ticks, meters, waveform parts follow the drawing), slow ambient loops of 1 s and over (Today's drifting gradient, pulses, the launch drawing), delays, `0`, and the springs. Shadows are counted in the test's report only (a named set comes with the parts kit).
- **The shrinking list:** every value that didn't match a name at Q40 stayed as it was and is listed in `tests/test_values.py` (`KNOWN`: kind · selector · property · value; `KNOWN_JS`: file · curve). The list may only get shorter: a new stray fails the test, and a stray that's gone but still listed fails with a "the list can shrink" message, so take its line off. Strays leave as their parts move onto the parts kit, so nothing is tidied twice. Rows and row-like cards keep their 0.98 / 0.96 shrink there until decision D06 (in Ivan's design decision register) turns it into a highlight. The list keys on the selector, not the line, so moving or reformatting a rule doesn't break it; the failure message gives the line.
- **Adding a value on purpose:** use the closest name first. If a part really needs a new value, add a name here and in `NAMED` in `tests/test_values.py` (with what it's for), in the build that needs it, and say why in its changelog; never add a raw value to `KNOWN`.
- **A new part starts from its closest relative** (app look skill, 6b): copy the corner, press and motion of the nearest existing part rather than picking new numbers. Design decisions themselves (D01 onwards) live in Ivan's register with their IDs (app look skill, 6c); this set only names values and guards them.
- Tests: `tests/test_values.py` (`VS_VALUES=named,css,js,guard,fixes`): the set's numbers and where it sits, every name used defined (in the stylesheet or as a MOTION spring), `MOTION.EASE` matching, no new strays and no stale list lines in `app.css` and `js/`, the guard itself (a new corner, press, curve and duration caught on a copy; named, exempt and removed values handled), and Q40's two fixes. It prints the counts (named uses, known strays by kind, shadows), so each build can see the list shrink.

### Keyboard (3.31, Q13)

Shortcuts from an iPad keyboard or a Mac never fire twice, while typing, or during a recording. Everything is in `KEYS` (helpers.js):

- **One typing check:** `KEYS.typing(e)` is true when the key's target, or whatever has the focus, takes text (an input, textarea, select or anything contenteditable). Nothing else writes its own (`tests/test_keys.py` checks the old copies are gone).
- **One place shortcuts go through:** a shortcut is `KEYS.add({when, run, repeat, typing, busy})`. gestures.js registers the only listener, `document.addEventListener('keydown', KEYS.route)`, after every other file's keydown listeners, so it sees what they did. `route()` skips a key that's `defaultPrevented` (another control used it) or `KEYS.composing(e)`, then gives it to the first shortcut whose `when(e)` is true, unless that shortcut is blocked by typing (`typing: true` allows it) or by `KEYS.busy()`, a sheet, the length picker (`CK.pk`) or a recording (`busy: true` allows it). It calls `preventDefault()` and runs it, except a held key (`e.repeat`), which only runs shortcuts with `repeat: true` (moves, never toggles).
- **The shortcuts:** Cmd + 1–4 (gestures.js; not on a session's step, `X && isFlow(U.view)`, and through `sgTabTap()` like the tab bar), Cmd + F, N, E and , (songs.js, `typing: true` as before, so Cmd+E is still Done while editing the lyrics), ↑ ↓ between songs (songs.js, `repeat: true`), and the track player's Space, I and O and its ← → (`repeat: true`) in track.js. Add a new shortcut the same way.
- **Cmd only on Apple devices:** `KEYS.mod(e)` is `metaKey` without Ctrl on an iPhone, iPad or Mac (`KEYS.apple`, from the platform or user agent; an iPad asking for the desktop site says Macintosh) and `ctrlKey` without Cmd elsewhere, so Ctrl+E, N, F and the rest stay text editing. Tests on the iPhone user agent press `Meta+…`; with `ua=None` (Linux) they press `Control+…`.
- **Controls keep their keys:** the length picker's wheels call `stopPropagation()` on ↑ ↓ (they used to open the next song too, and Set then went to the song the picker was opened on). A new control that uses a key should `preventDefault()` (and `stopPropagation()` if a document listener could also act on it).
- **Enter to confirm** uses `KEYS.enter(e)`: Enter, but not while composing (`isComposing`, or keyCode 229, which Safari gives the Enter that picks a word). Used by Search's field, the Songs filter, the title and artist in place, a mark's text and a take's comment and name.
- **Escape isn't a shortcut:** songs.js (capture), clock.js, search.js and events.js close the same things as before, in the same order.

### The pitch listener (3.52, Q37)

`PITCH` (`js/pitch.js`) reads the notes in a voice, for the song ladder and later for bridge-aware patterns (Q38) and key and scale lanes (Q39). It's one shared piece, like the pattern player: change how the voice is read here and every feature reads it the same way. Its numbers are `PITCH.SET` (they came from the pitch test Recon, 2 Nov 2026).

- **The detector** is pitchy 4.1.0 (McLeod method, MIT) with its FFT, fft.js 4.0.4 (MIT), in `js/pitchy.js`: built from the npm packages with esbuild's IIFE output, unchanged, as the global `Pitchy`, with both notices at the top. To update it, bundle the new versions the same way, keep the notices, and say so in the README's licence.
- **A take's line** (`PITCH.ofTake(id)` → a promise of the line, or null): the take decoded once (44.1 kHz, the louder channel), then one reading every 10 ms over a 2048-sample window. Frames quieter than 4% of the loudest (or 0.003) are skipped; a reading needs clarity 0.90 and 60–1500 Hz. Then `shape()`: islands under 40 ms dropped, octave slips fixed against the median of the 150 ms either side, a 25 ms median. A line is `{s, n, hop, first, firstT, dur, lo, hi, read}`: `s` is MIDI note numbers per 10 ms (NaN for no note), `first`/`firstT` the first note, `lo`/`hi` the 1st and 99th percentile, `read` how much read as a note. `PITCH.line(data, sr)` does the same for samples.
- **In memory only:** lines are kept in a Map while the app is open (`PITCH.got(id)` once read, `PITCH.forget(id)`), never saved and never in backups. A take that can't be read gives null and is tried again next time.
- **Jumps** (`PITCH.jumps(line)`): 2 semitones or more within 200 ms, steady (within 1.2) for 50 ms either side: `{t, from, to}`, `t` from the first note. **Held notes** (`PITCH.held(line)`): 250 ms or more within 1 semitone: `{t, d, m}` (m the median, not rounded).
- **Where two lines part** (`PITCH.part(a, b)`): both aligned at their first note, the longest run of 100 ms or more where `b` is more than 0.6 semitone from `a` (a gap in either breaks a run): `{at, len, t}` (t is its middle), or null.
- **Live** (`PITCH.live(analyser, fn)` → stop): reads an `AnalyserNode` (its `fftSize` is the window) on the shared frame clock (`AUDIO.frame`), at most every 10 ms, with the same clarity and the octave check against the last 150 ms; `fn(points, last)` gets `{t, m}` points. Use the recording's own `rec.mic.analyser(2048)`, never a second microphone or context, and keep any element found to draw into (look again only once it's no longer connected).
- **Drawing:** `PITCH.svg(lines, {w, h, lo, hi, dur, marker, dots, label, lanes})` draws note rows (C, E, G and A labelled), seconds along the bottom, and lines (`{a, col, on, key}`, `a` a line or live points) from their first note, with an optional dashed marker and (Q38) `dots`, points `{t, m}` ringed on the lines (`.pj`: Find your bridge's jumps); `PITCH.spark(line, col)` is a 64 × 24 line for a row. Colours go in `style`, so `var(--…)` works. **Scale lanes (Q39):** `lanes`, a function `(lo, hi) → [{m, name, home}]` (`SONGKEY.lanesFor(sg)`), draws the key's notes as faint bands (`.plane`, the home note `.plane.home` in the accent) labelled with their spelled names (home notes first, the rest 12 px apart) instead of the semitone rows and C, E, G and A; the chart gets `.laned` and "with scale lanes" in its label.
- Tests: `tests/test_pitch.py` (`VS_PITCH=lib,line,jumps,held,part,takes,live,tone`): the pinned copy and its notices, the settings, a steady note, quiet frames, islands, octave slips and vibrato, jumps (a crack, not a slide, a step or a breath), held notes, the parting spot (aligned, under 0.6, under 100 ms, the longest run), takes read once and never saved or backed up, the live line from a fake analyser on the frame clock, and `PAT.tone` (once, Repeat, one sound at a time, leaving the app).

### Key and scale lanes (3.54, Q39)

Sing a song in its key: the app finds the song's key, lays the scale over your pitch lines and suggests patterns from the library, in that key, that reach the note you're working on. `SONGKEY` in `js/key.js` (the name `KEY` was taken by storage.js). Render given by Ivan on 3 Nov 2026, 08:01; the prototype was "Prototype · Song ladder and bridge-aware patterns" (v2).

- **Libraries,** pinned like pitchy: `js/musictheory.js` is musictheoryjs 3.2.2's `detectKey` only (ISC, global `MusicTheory`) and `js/tonal.js` is tonal 6.5.1's Scale, Note and Key only (MIT, global `Tonal`), each about 32 KB, built with esbuild's minified IIFE output of an `export { … } from` line, with their notices at the top. To update, bundle the new versions the same way, keep the notices, and say so in the README's licence.
- **The key** is `sg.ext.key = {tonic, mode}` (see Songs): `tonic` spelled as on the key sheet (`SONGKEY.MAJ`: C, D♭, D, E♭, E, F, F♯, G, A♭, A, B♭, B; `SONGKEY.MIN` the same with C♯ and G♯), written as `Db`, `F#` and so on; `mode` `major` or `minor`. `SONGKEY.valid()`, `of(sg)`, `set(sg, k)` (null clears it, and an empty `ext` goes), `label(k)` ("B♭ major"). In backups with the song; `cleanSong()` calls `SONGKEY.clean(ext)`, which drops a key that isn't one of the 24 and keeps fields it doesn't know.
- **Finding it** (`SONGKEY.detect(id)`): every take of the song (`TAKES` with its `songId`) is read through `PITCH.ofTake()`, one at a time, then `profile()`: 12 bins counting every frame within 0.25 semitone of both its neighbours (`SET.steady`), at its nearest note. Under 150 such frames (1.5 s, `SET.enough`) it's "Not enough singing yet to hear the key" with Choose…. Otherwise `find()` (detectKey, the top two, spelled as on the sheet) and `verdict()`: the top two within 0.15 (`SET.close`) ask "Which key is this song in?" with both and Other…; otherwise "This sounds like F major" with Use and Other…; both say "From your takes. You only choose once for each song." The result is kept in memory per song until its takes change; "Listening for the key…" shows while it reads.
- **The key sheet** (VS-098 · Song key, `U.sheet = 'keyPick'`, `U.sd = {k: song id, tonic, mode}`): Major / Minor (`keyMode`), 12 notes as `.ladnote` buttons in a 4 × 3 grid (`keyNote`), and **Use <key>** (`keySave`). Switching the mode keeps the note (D♭ major ↔ C♯ minor). It opens on the song's key, else the key it heard best, else C major. Doors: Other…, Choose… and Change on Lines (`keyChange`), and the song page's **Key** row (VS-009 › key-row, under the track row, `SONGKEY.row(sg)`: "Not set · found from your takes, or choose it" until there is one).
- **Scale lanes:** on Lines and on the live line while a rung records (`SONGKEY.lanesFor(sg)` passed to `PITCH.svg` as `lanes`; see The pitch listener › Drawing). Names come from tonal's scale (`nameIn(m, k)`: B♭4 in F major, C♭4 in E♭ minor), finding the octave by `Tonal.Note.midi`. A **Scale lanes** chip on Lines (`keyLanes`, `.keychip`, beside the line chips, only once there's a key) turns them off and on for this device (`vocalLook.lanes`, on unless switched off). Descriptive only: the lines aren't coloured.
- **Lines** (`APPL` `keyPart()`, after Notes of the line, from two rungs, once the lines are read): the Song key block (`.keyblk`), then **Practise in <key>** (`.keyprac`) once there's a key.
  - **The note to work on** (`SONGKEY.target(a, sp, k)`): from the trill's line (else the hum's), the held note covering the parting spot (or within 0.5 s of it), else the line's top held note (else its `hi`); snapped to the key (`snap()`, the nearer scale note, a tie going down). "Where the words part (around 2.3 s) sits on A4, the 3rd of F major." or "The line's top note sits on …". `degree()` names it (home note, 2nd … 7th).
  - **The patterns** (`SONGKEY.suggest(k, m)`, at most 3, `SET.most`): every `LIB` pattern with notes, played from a key note `kn` that is the key's home note, so that its highest note is the target, every note is in the key and none is below A2 (MIDI 45, `SET.floor`). Then one from each group in the order riffs (`r`), flips (`x`), warm-ups (`w`), and the rest in library order to fill. If none peaks on the target, patterns that pass through it instead (each placed so the highest of its notes that can sit on the target does), and the foot says so. A minor pattern can't show in a major key, since its ♭3 isn't in the scale.
  - **Each row** (`.keypat`): Play (`keyHear`: `PAT.hear()`, once, in the player's sound, through NOW; tapped again it stops; Hear both or a take starting stops it, and so does leaving Lines, `SONGKEY.after()`), then the name, the range (lowest–highest, spelled in the key) and what it trains, as a door (`keyGo`, `data-zk="keyp" data-push`) into the player.
- **Practise in <key>** (VS-097, `U.view = 'keyp'`, `U.keyp = {id, k, m}`, `U.keypFrom`): `PAT.guest()` then a pushed page with the song and the note, the pattern drawing (`PAT.card()`) and the pattern player's dock, on that pattern and note with Stay on this key on. Back (`keyBack`) returns to where it came from. Nothing about it is saved.
- **Notes of the line (Q37):** once the song has a key, each held note is snapped to the key and spelled in it, and the foot says "From your trill, matched to F major".
- **Not in Q39:** key changes within a song, chords, moving a song to another key, any score or right/wrong colouring. Q38's bridge band is on the exercise drawing, not on pitch lines, so the lanes have nothing to replace there.
- Tests: `tests/test_key.py` (`VS_KEY=lib,find,spell,suggest,lines,sheet,player,notes,data,sizes`).

### The session clock (3.42, Q22)

The timer pill opens a ring (`SCLOCK` in sclock.js, drawn by `renderSheet()` while `U.clock`). Render given by Ivan on 31 Oct 2026; the prototype was an inline widget in that chat ("session clock prototype, swipe dismiss"), whose colours and demo data were stand-ins.
- **What it shows** (`model()`, from the stamps only: `X.fE`, `X.rE`, `elapsedSec()`, as Progress's split reads them): one ring of three slices in the step colours (`--cF`, `--cR`, `--cA`), each as long as `usual()` for that step: the median of the last 10 sessions with a `split` for it (`mixed` sessions have none), or 22, 19 and 14 minutes until there are 3; cached until the number of sessions changes. Song practice is one slice round the ring (usual: the median of its last 10, or 20), with no tick. The step on now fills `secs / usual` of its slice, at most all of it; a logged step fills its whole slice; nothing changes colour or says "over". A tick (`.scktk`) marks the end of the current slice, and "Usual move-on ~N min" sits under the ring. Rows show each step's time in its colour; steps not reached show "~N min". The centre is the total and "Step · m:ss"; tapping it (`sckSwap`) shows the step's time first, kept in `vocalClock`. Every figure is `tabular-nums`, and `tick()` (from the one-second interval in gestures.js) changes text and the ring's markup in place, so digits never animate.
- **Paused:** `.sck.paused`: the slices breathe (`sckBreathe`, opacity only; none with Reduce Motion or motion off), the numbers grey, "Paused · for N min", "Paused time isn't counted", and the main button is Resume.
- **The main button** (`sckMain`) clicks the pinned button (`#dock [data-a=cta]`), so it does exactly what it does (Log, Skip, Finish, the long-session check), with its words and look (`OP.label()`, `OP.look()`). After a Log the clock stays open on the next step. Finishing from it (a focused session that lands on Session saved with no sheet): `finished()` keeps the clock over the saved screen with every slice filling to its end (a CSS transition on the gentle spring), "N min / Session saved" in the centre, `SAVED.line()` under the ring (Q21's own line, not a copy) and Done (`sckDone`), which calls `SAVED.done()`.
- **Opening and closing:** `open()` grows it out of `#timer` (a transform from the pill's box, on `nav`), `close()` closes it at once (`U.clock` false, the layer redrawn, so the page can be tapped straight away) while a still copy (`.sckghost`, on `<body>`, nothing tappable) shrinks back into the pill quicker (300 ms), from wherever a swipe left it; the random taps (motion on) found the clock still in the layer while it closed. ✕, the dimmed page (`.clockscrim`) and Escape close it. Reduce Motion: fades. Motion off: no animation.
- **Swipe to close:** touch only, anywhere on the clock except `[data-own-gesture]` (the step-time slider) and fields. It locks after 10 px if mostly sideways (1.3×), either way; the clock follows the finger and shrinks towards the pill (sideways only with Reduce Motion). Past `SWIPE_CLOSE` (a fifth of its width) or a flick (0.45 px/ms, the same way) it closes; otherwise `MOTION.spring()` brings it back at the finger's speed, and a touch catches that spring where it is. A vertical move is left to scrolling. `SCLOCK.swallow()` drops the tap that ends a swipe. Zoom's swipe back never starts while the clock is open.
- **Undo on Log** (`logged()`, from `OP.advance()`): a 5 s `toastBtn` with Undo, which puts the stamps back as they were and steps back (`OP.stepTo()`), keeping the clock open if it was. It does nothing if any stamp changed since; finishing removes the toast.
- **Fixing a step time** (`sckFix` on a finished step's time; not Song practice): hold and slide on `#sckSlider` (pointer events, `touch-action: none`, arrow keys a minute at a time) from 1 to at least twice the usual length, "Logged N min", Save time. `shift(d, keys)` moves `X.pausedTotal` and every later stamp by the same seconds, so that step has its new length, every other step keeps its own and the total changes by the difference. Progress's split, worked out in `finishSession()` as before, follows.
- **The screen stays on** (`AWAKE` in helpers.js, one wake lock that Song Clock's Stay awake shares: `AWAKE.set(who, on, cb)`). `wake()` wants it while a session has a `start`, isn't paused and the app is on screen; it runs after every `render()`, on `visibilitychange`, on start and on pause. "Screen stays on" is a short toast when the lock is granted at the start (`newSession()`; not on song practice's first take, which is mid-take) and on Resume. No `navigator.wakeLock`, or a refusal, just means no lock and no toast.
- **Away and picked up:** while on screen the draft's `seen` is updated every second (saved every 15 s); hiding the app or `pagehide` writes `seen` into the stored draft only if it's still this session's (`left()`), never over anything else. Coming back (`back()`, on `visibilitychange`, or at launch from `boot()`, measured before anything updates `seen`) after more than `AWAY_MIN` (10) minutes with the clock running opens the `away` sheet ("You were away N min"; asked once nothing else is open). **Take it out** adds the gap to `X.pausedTotal`, capped at what the step that was running has had, and moves any stamp made since coming back with it; **Keep it, I was singing** (or closing the sheet) changes nothing. A launch with a session running toasts "Session picked up".
- Tests: `tests/test_sclock.py` (the ring's slices, colours, fills, tick and line, logged and over-long steps, ~N min, usual lengths from the last 10; paused, breathing, Resume, digits never animating, Reduce Motion; steady digits; the swap remembered; ✕, the dimmed page and Escape; the zoom out of the pill and back in slow motion; Reduce Motion fades; swipes both ways, mid-swipe, spring back, a flick, a scroll and the slider; finishing into the saved line and Done, motion on and off, and the long check; Undo after Log from the pinned button and the clock, a stale Undo, the split; fixing both steps and the split; the floating window's ring and pause; the wake lock at start, pause, Resume, hidden, shared with Song Clock, finished, missing and refused; away and picked up, Take it out (capped), Keep it, short gaps, paused, a stamp made since coming back; Song practice's one slice; 390 and 375 in light and dark).

### Bridge-aware patterns (3.53, Q38)

The pattern player knows your bridge and guides you through it (thinner, quieter) instead of letting you push. Render given by Ivan on 3 Nov 2026, Build on 4 Nov 2026; the prototype was "Prototype · Song ladder and bridge-aware patterns" (v3). All of it is in `js/patterns.js` (`PAT`), on the shared pitch listener (`PITCH`) and audio service (`AUDIO`).

- **Your bridge** is `D.prefs.pat.voice.bridge`, `{lo, hi}` as MIDI notes (`PAT.bridge()`, `PAT.setBridge(lo, hi)`, lowest first). It travels with Your voice, so it's in backups; changing the voice type or a stepper keeps it. `PAT.clean()` drops only a bad bridge (not whole numbers, or the wrong way round) and keeps the voice.
- **Find your bridge** (VS-096, `U.sheet = 'bridge'`, `PAT.bridgeSheet()`, state `FB`): Start (`bfStart`, in the tap) stops whatever plays (`NOW.stop()`), opens the microphone (`micOpen()`, below) and draws the slide live into `#bfLive` about ten times a second, found once. The readings go into a 10 ms line (`FB.s`; a short gap holds the reading before it, never drawn in between, which would smooth a jump away) that `PITCH.jumps()` reads, and each jump is ringed. Done (`bfStop`), 20 s or leaving the app ends it. The first jump suggests the zone: 2 semitones below its lower note to 1 above. With no jump, or Set it by feel (`bfFeel`), From and To start on the saved bridge (else your top − 5 to − 2). It shows the highest note reached (the 98th percentile). Use this bridge (`bfUse`) saves and closes; Try again listens again. A blocked microphone says so and keeps the steppers. Closing the sheet lets go of the microphone (`PAT.after()`). Doors: the exercise page's bridge line (`#pcBridge`) and Settings › Your voice › Your bridge (both `patBridge`).
- **The drawing** (`svg()` for `pc` only): `bandSVG()` shades the zone behind the round shown, only where it meets the round's notes, labelled at whichever end has no ringed note; notes in the zone get an orange ring (`.pring`).
- **The bridge line** (`bridgeHTML()`, painted in place): "Bridge E4–G4 · rounds X–Y cross it. Those notes play softer." with Change, or Find your bridge with Find it. The rounds are those of `route()` with a note in the zone.
- **Softer notes:** `round(k, t0, p, b, soft)` with `soft` (the exercise page only, not the Patterns page) plays notes in the zone at `BRIDGE_VOL` (55%) and marks them `br`. The chord and the held note underneath are unchanged. `runs[].vols` lists each round's note volumes for the tests.
- **The cue** (`#pcCue`, over the drawing): `tick()` shows it while a `br` note is lit, when `bcue` is on (Settings › Pattern player › Bridge cue, on by default). `cueOf(word)` gives the narrower vowel (ah → uh, ee → ih, eh and ay → ih, oh → uh); anything else (hmmm, ng, brrr, oo) gets "Thinner · quieter". The word is the vowel cue's for the round, or the exercise's one syllable.
- **Stop one past last time** (`stopLast`, Settings › Your voice, beside Stop at my top note): `route()` ends with the first round whose top is above Last time. With Stop at my top note on too, the earlier stop wins. With no Last time the route is whole, and the card says how to set one.
- **Last time** (`D.prefs.pat.ex[key].last`, `{m, at}`): the highest round top held cleanly while listening: 250 ms or more within 1 semitone of the round's top (`HOLD`, `heard()`), with no gap. It only moves up, quietly (`heldTop()`, no toast), shown as "Last time: F4 · today" (`#pcLast`). While playing, `route()` uses Last time as it was when Play was pressed (`S.lastSnap`), so the route holds still. Without listening it never changes.
- **Listen while I sing** (`listen`, off by default; the switch on the card, `#pcListen`, and in Settings › Pattern player): only while the pattern plays. `play()` calls `listenStart()` in its tap; `end()`, switching it off, another sound starting, leaving the page or the app call `listenStop()`. Your voice is a dot (`.pvoice`) and a 1 s trail (`.ptrail`) on the drawing, at the playhead's place and the note's height for the round (`yOfNote()`), painted by `tick()` from elements found once per round. "Headphones in, so it only hears you" shows while it's on.
- **The microphone** (`micOpen(fn, onFail)`): the same processing-off `getUserMedia` as a recording, through `AUDIO.listen()` (the shared context, which only ever hears the microphone) and one `analyser(2048)` read by `PITCH.live()` on the shared frame clock. The pattern's sound stays on PAT's own context. While it's open `navigator.audioSession.type` is `'play-and-record'` (where it exists), then back to `'playback'`. Nothing is recorded.
- **Not in Q38:** recording on the exercise page (Exercise takes, Not scheduled), key and scale lanes (Q39), and any score or right/wrong colouring (there are none).
- Tests: `tests/test_bridge.py` (`VS_BRIDGE=data,sheet,page,cue,stop,listen,sizes`).

## Screen IDs

Since 3.50 (Q36) every screen, sub-page, sheet and overlay has a permanent ID, `VS-001` onwards, so a note, a test, the Atlas or a request can point at it in a few characters ("VS-009, the button's too low") and still point at the right thing after it's renamed, moved or redesigned. Its main parts have names (`VS-001 › start-session-button`) and the main journeys have flow IDs (`F-01 · Focused session`). The rule comes from Ivan's app workflow (permanent IDs, never reused).

- **The register is `js/register.js`** (`SCREENS`), plain data loaded before everything else. Each screen has: `id`, `name`, `area`, `kind` (Tab, Screen, Sub-page, Sheet, Overlay), `key` (the code key, below), `aliases` (older keys, including the Atlas's), `docs` (the exact `README.md` or `MAINTAINING.md` heading that explains it), `status` (`Live`, or `Retired in <version>`) and `parts`. `shared` holds parts named wherever they show (the tab bar, Search, Settings, Back, a sheet's Close). `flows` holds the journeys: each step is a screen ID, with the part tapped to get to the next (and a `state` where one screen appears at several moments).
- **Code keys:** `tab:<U.tab>`, `view:<U.view>`, `view:set/<U.setPg>` for a Settings page, `view:guide/home`, `/how` and `/mark` for the Marks guide (every mark's page is one screen), `sheet:<U.sheet>`, and `overlay:clock`, `overlay:window`, `overlay:launch`, `overlay:peek` for what's drawn outside `render()`. `SCR.viewKey()` works out the screen's key.
- **On the page** (`SCR` in ui.js): `render()` ends with `SCR.screen()`, which sets `data-screen` on `#app` and `data-name` on the register's parts in `#app`, the bar, the dock and the sidebar; `renderSheet()` calls `SCR.sheet()` for the sheet (or the session clock) in `#layer`. The floating window (`fwEl`, `fwClean`), the peek card (`showPeek`) and the launch screen (at boot) call `SCR.mark(el, key)`. The parts are found by their `sel` inside that screen, so the markup only needs its usual `data-a`.
- **States of one screen share its ID** (first launch, a session running, dark mode, recording): flows and the Atlas name the state beside it (`VS-004 · recording`).
- **A screen with no entry** gets `data-screen="VS-???"` and one console warning, and the tests fail on it (`test_screens.py`, and the random taps in `test_fuzz.py`).
- **Show screen IDs** (Settings › Appearance, `vocalLook.ids`, this device only): `SCR.label()` keeps `#scrid`, a small grey label in the top corner just below the bar, showing the screen's ID and then the open sheet's (`VS-009 · VS-050`). Taps go through it, and it never covers the bars or the tab bar.
- **Adding a screen:** give it the next number at the end of `screens` (whatever its area: the grouping by area was for the first numbering only), with its key, name, area, docs heading and parts. Add it to a flow if it's on one.
- **Renaming or moving one:** change its `name`, `key` or `docs` on its line, and put the old key in `aliases`. Never change its `id`.
- **Retiring one:** set `status: 'Retired in 3.xx'` and leave the line. IDs and flow IDs are never reused or renumbered.
- **Parts:** lower case with hyphens, named by what the part is (`done-button`, not `bottom-right-button`). A part that moves keeps its name; change its `sel`.
- **The changelog:** each version's `Screens:` line lists the screens it changed (see The Changelog page).
- The register is public: screen names and code keys only, never personal data.
- Tests: `tests/test_screens.py` (the register's shape, every screen the code can show has an entry and the right `data-screen`, part names, docs links, flows, the label, the Changelog's Screens line, and the saved-data list against every storage key in the code).

## Visual App Atlas (Q30)

A developer tool that shows every screen and sheet as saved screenshots, with where each button goes, a map of how they link, notes on any part of a screen that Claude can read, an export for Claude and what changed since the last scan; easy to use on a phone too. It scans the app with the tests' sample data (never real data), changes nothing in the app and has no app version. Since Q31 it runs on the **Atlas kit** (`imperialfox/atlas-kit`, one Atlas for any app): `tools/atlas/` holds Vocal Sessions' settings (`screens.py`) and a pinned, unmodified copy of the kit in `tools/atlas/kit/` (its version is noted in `tools/atlas/README.md`). How it works, its rules and its files: [tools/atlas/README.md](tools/atlas/README.md).

**On the Mac, one command** (from the repo folder, with the tests' Playwright installed):

```
python3 tools/atlas/atlas.py           # scan (about 5–10 minutes), then open the Atlas in the browser
python3 tools/atlas/atlas.py --view    # open the last scan again
python3 tools/atlas/test_atlas.py      # the Atlas's own tests (about two minutes; not part of tests/run.py)
```

**From a Claude chat:** say "rescan the Atlas". Claude runs the scan and updates the private Atlas page on claude.ai. Say "check my notes" and Claude reads the notes left on that page (and on any prototype listed there), in note format v1.

- **Scans and notes stay out of git.** Scans go in `tools/atlas/data/scans/<date-time>/`, which is git-ignored: the repo is public and GitHub Pages serves everything in it. Every scan is kept, so the next one can be compared with it. Notes live only on the private Atlas page; "Copy as queue ideas" turns chosen notes into text for RENDER_QUEUE.md › Not scheduled.
- **Never edit `tools/atlas/kit/`.** Change the kit in its own repo, release it, then copy the release in (`tools/atlas/README.md` › Files says how); `test_atlas.py` fails if the copy differs from `kit.sha256`.
- **Screens are read once they've settled** (`where()` in `screens.py`): animations finished, loops held, an open sheet steady for three frames. If a rescan of an unchanged app calls a screen "looks different", something on it is still moving when it's read: look there first.
- **Screens are keyed by their screen IDs** (`js/register.js`, Q36), read off each screen, so notes and the map layout stay put through renames. A screen with no register entry shows as "No ID yet · suggested VS-0xx" (add it to the register in an app build).
- **The screen list comes from the code** (`inventory()` in `tools/atlas/screens.py`): `render()`, `renderSheet()` and the functions it hands sheets to, Settings' `TITLE` pages, and every `U.tab`, `U.view` and `U.sheet` set anywhere. A new screen shows up by itself, as "Not captured yet" until a button the scan taps opens it, and a removed one as gone from the code.
- **When you add a screen:** if the scan can't reach it by tapping (it needs set-up the sample data doesn't have), add a starting screen to `ROOTS` in `tools/atlas/screens.py`, opened through real buttons (set-up goes in `load()` or `SETUP_JS`; the only other steps are waits, `UNTIL`, and holds, `HOLD`). Add its doc sections to `KEY_DOCS` there; `test_atlas.py` fails if a section it names is renamed or removed. Give it a one-line caption in `CAPTIONS` (the test fails without one), and if it only opens after a swipe, a hold, a wait or a file picker, a hand-written door in `DOORS`.
- **Starting states, flows, captions and doors (Q35):** the coach video, recording and takes, How did it go?, the peek card, Check timing's Overlaps, Past the new end and the rescued copy each have a starting state ([tools/atlas/README › Starting states](tools/atlas/README.md#starting-states-flows-captions-and-doors-q35)). `FLOWS` walks the register's F-01 and F-02; when a flow's buttons change in the app, change its steps in `screens.py` in the same build (`test_atlas.py states` walks both).
- **When you rename a doc section** the Atlas links to ("Explained in"), update `screens.py` too.
- **Buttons the scan never taps** (microphone, files, sharing, replacing or deleting data) are listed in `SKIP` in `screens.py`, each with the reason the Atlas shows. The kit checks each button's action, value and label against them.

## Releasing

`python tools/release.py 3.7` updates `APP_VERSION` and `RELEASE_DATE` in `index.html`, the README badge and "Current version" line, and adds a `## 3.7 · date` section to `CHANGELOG.md` with a placeholder headline and note. The release test fails until both are replaced with the real headline and changes.

Version numbers: **major** for a redesign, **minor** for new features, **patch** for fixes.

From 3.50 every version's notes end with a `Screens:` line naming the screens it changed by ID (`Screens: none` for data, tests or behind-the-scenes work). See The Changelog page above and Screen IDs below.

The app checks for a newer `APP_VERSION` on pull to refresh, so a release reaches the phone the next time Ivan pulls down on Today or Progress.

## Style

The app follows Apple's design language for iOS 26/27 (Liquid Glass imitated in CSS), with British English in plain, friendly words. Everything must work on iPhone, iPhone landscape, iPad and Mac, in light and dark mode.
