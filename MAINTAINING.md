# Maintaining Vocal Sessions

Notes for whoever works on the app next, whether that's Ivan, a new Claude session or anyone else. The [README](README.md) covers what the app does; this covers how it's built and how to change it safely.

---

## The short version

1. Change the files in `js/` and `css/` (or `index.html` for markup, `sw.js` for offline behaviour). Practice content (exercises, words, write-ups, goals) is all in `js/content.js`.
2. While building, run `python tests/run.py quick` (about a minute and a half) or just the files you're changing. Before pushing, run `python tests/run.py` (about 3½ minutes). Everything must pass.
3. Run `python tools/release.py 3.7` with the new version, and write the changes in `CHANGELOG.md`.
4. Run `python tests/run.py release` to check the version agrees everywhere.
5. Push to `main`. GitHub Pages publishes it within a minute or two, and the **Tests** check runs on GitHub.

**Working with Claude:** The call signs have separate meanings. **Render** approves the exact named scope; it does not start implementation or authorize a push. **Build** starts implementation only after that scope has Render approval. Build follows the checks and release steps below when applicable.
- Research, planning and prototyping may happen before approval, but do not edit the app in the repo until Ivan separately says **Build** for a Render-approved item.
- Each build happens in a **fresh chat**, started from a short [handoff note](HANDOFF.md). Implement only that approved scope; don't bundle other queue items.
- Tests are tiered: `quick` or single files while building, the full suite once before pushing. The full suite runs files side by side.

**Handoffs between chats and models:** [HANDOFF.md](HANDOFF.md) defines Recon, Blueprint, Render, Build and Debrief, with a template to copy. Queued app work and each item's gate status are in [RENDER_QUEUE.md](RENDER_QUEUE.md).
- Prepare a handoff when a stage ends (an idea agreed, a prototype approved, a build pushed), when switching between Gemini, ChatGPT and Claude, and before every fresh build chat.
- Start the next chat with it. The receiving model checks it against the repo (the code wins on what's built), confirms the required gates, then does only the next action it names. One model builds each change; the others explore or review.

They're plain scripts, not modules: they share one global scope, and a file can use anything from the files before it. Nothing runs while the files load except in `boot.js`, so the order only matters for `boot.js` being last. Inside each file, sections are still marked `/* ===== Name ===== */`.

The code is formatted with Prettier (`npx prettier@3.3.3 --write --single-quote --print-width 120 --trailing-comma es5 js css`). Formatting is optional, but keeps changes easy to read.

### Every file has a version in its address

`index.html` loads `js/storage.js?v=3.7.1` and so on. A new version means new addresses, so no phone can mix an old file with a new page, and the offline copy can keep each version complete. `tools/release.py` updates every `?v=`; the release test fails if one is missed or a listed file doesn't exist. **Add a new file by adding its `<script>` (or `<link>`) to `index.html` with the same `?v=`.**

## Where data lives

Everything stays on the device. There is no server.

| Where | Key | Holds |
|---|---|---|
| localStorage | `vocalTracker` | All saved data (`D`): sessions, song practice, months, exercises, songs, words, last backup |
| localStorage | `vocalDraft` | The session in progress (`X`), so it survives closing the app. Song practice only has a `start` (and a draft) once its first take starts recording |
| localStorage | `vocalBackupLog` | Backup history for this device |
| localStorage | `vocalSongPrefs` | This device's song sort order and recent searches, the marks layer shown (`mkLayer`, 3.27), Song Clock's settings: `marksPlaying`, `blurAhead`, `snapping`, `stayAwake`, `pins`, the track player's `trkLevel` (0–3) and `trkSpeed`, and Search's recent searches `findRecent` (3.22) (not backed up) |
| localStorage | `vocalWindow` | The floating window's corner on this device, `{corner: 'br'}` (not backed up) |
| localStorage | `vocalLook` | This device's look (3.23, Settings › Appearance): `{grad: false}` when Today's gradient is switched off; absent means everything is on its default (not backed up) |
| localStorage | `vocalBeforeUpgrade` | Up to 3.28: the copy from before the last data upgrade. Since 3.29 (Q11) it's moved into `vocalSafety` once at launch and cleared from here |
| IndexedDB `vocalTakes` (version 2) | store `takes` | Recordings, with their audio as Blobs |
| IndexedDB `vocalTakes` | store `undo` | The copy kept for 30 days after a restore |
| IndexedDB `vocalCoach` (version 1) | store `video`, key `v` | The coach video: `{name, size, type, dur, added, blob}`. Never in backups; Reset all data leaves it |
| localStorage | `vocalCoach` | The coach video's place, speed and Loop on this device, `{t, speed, loop}` (not backed up) |
| IndexedDB `vocalSafety` (version 1, Q11) | store `copies`, keyed by name | The safety copies (`SAFE`): `vocalBeforeUpgrade` is `{from, to, at, data}`, the data as it was before the last data upgrade, kept for 30 days; `rescued:<ms>` is `{at, why, text, bytes, appVersion}`, saved data that couldn't be read (`why: 'unreadable'`) or that had a song that couldn't be checked (`'song'`), exactly as it was stored, kept until deleted in Settings › Backup. Never in backups; restores and Reset all data leave it. Counted in Storage with Sessions and songs |
| IndexedDB `vocalTracks` (version 1) | stores `audio` and `peaks`, key: the song's id | Song tracks (3.19): `audio` is `{name, size, type, dur, added, blob}` (the file as imported), `peaks` is `{p: Uint8Array, rate: 50, dur}`. Never in backups; restores and Reset all data leave it; deleting a song or Remove track deletes its entries |

`cleanData()` checks anything loaded or restored and drops what's malformed, so damaged data can't stop the app starting. Each song is checked on its own: one that makes `cleanSong()` throw is dropped alone and counted in `CLEAN_DROPPED` (Q11). `migrate()` fills in defaults and then runs `upgradeData()`; `normX()` upgrades older drafts.

### Save safety (3.29, Q11)

Nothing the app does may lose saved data, a take or a session in progress without saying so.

- **Saved data that can't be read** (`load()`): when `vocalTracker` won't parse, isn't an object, or `cleanData()` fails, its text goes to `SAFE.rescue(text, 'unreadable')` and the app starts empty. When a song had to be dropped, the data as it was goes to `SAFE.rescue(text, 'song')` and the rest loads. Either way Ivan gets one toast pointing to **Settings › Backup › Rescued data**, where each copy can be saved as a `.txt` file (`rescueSave`) or deleted (`rescueDel`, with confirmation). A copy is made once per launch (`rescuing`), so pull to refresh doesn't make another.
- **Saving waits for a copy** (`holdSaves(promise)`): while a safety copy is being written, `save()` only remembers that it was asked, and saves once every hold has settled. The rescue and the pre-upgrade copy both hold saves, so the copy always exists before anything is saved over what it copies.
- **Saving can be switched off for a launch** (`lockSaves(why)`, `SAVE_LOCK`): when the damaged data can't be copied anywhere (`'uncopied'`), localStorage can't be read (`'unreadable'`), or reading or upgrading the data threw at launch (`'boot'`). The stored data is then left exactly as it was, and a toast says changes won't be saved this time. Drafts still save.
- **One IndexedDB helper** (`IDB.define(name, version, stores)` → `{open, tx, each, close}`): every database goes through it (`TAKES_DB`, `SAFE_DB`, and `CDB`, `TDB`, `XDB` inside coach.js, track.js and takes.js). `tx(stores, mode, fn)` settles on complete, error or abort (aborting itself if `fn` throws), so a save never hangs without a word when storage is full. After a failure the connection is dropped, and the next call opens a fresh one; a connection the browser closed is reopened once. An open that stays blocked gives up after 4 s. `each(store, fn)` reads every entry and never rejects. `define()` creates a store only when it's missing, and the names, versions and stores are the ones listed above.
- **Recordings that can't be read** aren't the same as none: `allTakes()` gives `null`, `refreshTakes()` keeps the list as it was, `TAKES_READ` stays false so `TAKE`'s tidy-up doesn't forget waveforms, an export fails with its toast rather than leaving the recordings out, and a restore stops before replacing recordings it couldn't copy.
- **A take that fails to save** (`saveRec`): it's kept in `UNSAVED` (`{t, r, xs}`, the take with its blob, the recording, and which practice it was recorded in) and a toast offers **Retry** (`toastBtn`). Retry, the app coming back to the screen and the next take that saves all try again (`retryUnsaved`); a take saved later joins its practice only if that practice is still the one running (`X.start === xs`). The song practice it started carries on.
- **`saveDraft()`** warns when it fails, at most every 10 seconds.
- **Startup** (`boot.js`): each step runs through `bootStep()`, which records what went wrong in `BOOT_ERRORS`. If the first draw fails, `#app` shows a short message with Try again; the launch screen goes whatever happens (`bootFinish`, and a last-resort timer), and a toast says something went wrong.
- **Longer toasts** use `toast(text, ms, 'long')`, which wraps onto a second line; `toastBtn(text, label, fn, ms)` adds one button in the style of Song Clock's Undo toasts.

### Data version

Saved data carries `schema` (currently 4, from 3.27; 3 was 3.18, 2 was 3.8, 1 was 3.7). Step 4 moves the older Annotate marks into the layered `marks` (see Marks). Step 3 changes nothing: it marks data that may hold song timing. To change the shape of saved data:

1. Add a numbered step to `UPGRADES` that changes `D` in place, and raise `SCHEMA` to match.
2. Steps run in order the first time the new version opens, and whenever an older backup is restored. Before they run, the data is copied to the safety copies (`SAFE`, key `vocalBeforeUpgrade`, in IndexedDB since 3.29), and saving waits until the copy is there.
3. Add a test in `tests/test_data.py` that loads data from before the step and checks the result.

A backup whose `schema` is higher than the app's shows "Made by a newer version" before restoring.

### Songs

Each song in `D.songs` is its own record. Songs from before 3.8 have only `id` and `name`; everything else is optional.

| Field | Holds |
|---|---|
| `id`, `name` | Never change. Recordings (`songId`) and song practice (`songId`, `songName`) point at them. `name` is the title |
| `artist`, `pinned`, `added` | Artist (may be empty), pinned on Today and at the top of Songs (at most 3), when it was added (ms) |
| `practised` | When a take of it was last recorded (ms), set when a take is saved |
| `original` | The lyrics exactly as pasted. Never edited, so damaged lyrics can be rebuilt from it |
| `sections` | `{sid: {label, cue, lines, marks, held, ann, orphans}}`. `lines` is an array of lines, each an array of words. `marks` and `held` are the layered marks (3.27, see Marks below). `ann` and `orphans` are the same marks in the shape 3.26 read (`ann` maps `"line:word"` to `br`, `run`, `up`, `dn`, `v`, `nt`, `check`, `was`; `orphans` are marks whose word was removed), kept so a backup still opens in 3.26. This version only reads `marks` |
| `timing` | Song Clock (3.18), optional; none means not synced. `{len, real, est, slots: {o: {lines: [[start, end\|null], …], anch, marks: [line…]}}}` in seconds. See Song Clock below |
| `track` | Track player (3.19), optional: `{name, dur}`, the track's file name and length in seconds, so a song restored without its audio knows it had one. The audio itself is in `vocalTracks` |
| `loop` | The song's last loop (3.19), optional: `{start, end, on}` in seconds. Kept even without the track (like `timing`) |
| `order` | The running order `[{o, sid}]`. Linked repeats share a `sid`; each `o` is one place in the song, and takes recorded from a section carry it. Unlinking and moving sections never change an `o` |

`cleanSong()` checks each song on its own when data loads or a backup is read: bad values are dropped, marks on missing words and order entries for missing sections are removed, fields it doesn't know are kept, and if the lyrics are unusable but `original` is there, they're rebuilt from it. Practised dates come from recordings (`TAKES`) and `practised`, whichever is later.

### Recall

Recall is a song mode (`U.sMode = 'recall'`) that hides lyrics without changing the layout: `maskText()` wraps hidden letters in `.hx` spans (`aria-hidden`), which are transparent with a rounded pill drawn by `.hx::after`, so every word keeps its width. `U.sHint` is the level (0 Full lyrics to 4 Blank) and `U.sOrder` is `start` or `end`. Neither is saved, and entering Recall always resets them. Tapping a `.rl` line adds `.peeking` for `peekSecs()` (only one line at a time); holding one for `HOLD_MS` adds `.peeking.held` until the pointer lifts. Neither re-renders.

**Labels above words (3.17; every layer's since 3.27):** a word with a label is `.w.hv`, holding the label `.v` (a centred `display: table` block) above the word's own text `.wt`. The word's inline-block is as wide as the wider of the two and its baseline is the word's, so labels push their neighbours apart instead of overlapping, and only lines (or wrapped parts of lines) with a label get taller. Nothing is absolutely positioned any more. A run's wavy underline is on `.wt` for labelled words, so it never runs under the label. test_lyrics' `singas()` checks no label overlaps a lyric, a mark or another label at four sizes, in Practise, Recall and Perform.

The only Recall setting is **Peek length**, `D.prefs.peek` (1, 2, 3 or 5 seconds; missing means 2). `D.prefs` holds settings that travel with backups; `cleanData()` drops values it doesn't know.

### Motion

Everything that moves uses `MOTION` (`js/motion.js`), so the app feels the same everywhere and later features never add their own easing.

- **Springs:** `gentle` (ζ 0.82, 1.9 Hz: rows, capsules, sheets, fades), `nav` (ζ 0.86, 2.2 Hz: moving between pages, a little quicker) and `ripple` (ζ 0.6, 2.4 Hz: peeks and small pops). CSS uses `var(--dur-gentle)` and `var(--ease-gentle)` (and so on); JS uses `MOTION.animate(el, frames, {spring, delay, ms, fade})`, which does nothing (or a short fade with `fade: true`) when motion is off.
- **Stagger:** `MOTION.stagger(i, 'word' | 'row' | 'bar')` gives 30, 45 or 30 ms per item, for `MOTION.animate`'s `delay` (which applies the speed, so the stagger itself doesn't, since 3.13).
- **Reduce Motion** (the iOS setting, or forced On or Off in Settings › Accessibility since 3.21: localStorage `vocalReduce`, `'on'`/`'off'`, absent = Match iPhone) and **speed:** `MOTION.reduced()` reads both; `MOTION.on()` is false with Reduce Motion or speed 0. `MOTION.setSpeed(4)` is slow motion for tuning on a device, `setSpeed(1)` puts it back; it's kept in localStorage `vocalMotion`, never in backups. With motion off, every `--dur-*` is `0ms` and `<html>` has `motion-off`.
- **Distance blur:** `MOTION.blur(d)` (up to `BLUR_MAX`, 1.5 px, and 0 with Reduce Motion), `MOTION.dim(d)` (down to 0.3) and `MOTION.dimLabel(d)` (labels only dim, down to 0.45), where `d` is how many lines away from the focus. Song Clock's Blur ahead should reuse these.
- **Tests run with motion off:** the harness sets `vocalMotion` to `0` before each page loads. A test that needs real motion passes its own `init` setting it to `1` (see `test_lyrics.py`).
- **The launch ripple (3.13, `js/launch.js`, `LAUNCH`):** the app's signature moment. On a cold launch the icon's six sound-wave bars pulse in turn (`BAR`: 520 ms each, 70 ms apart, from 120 ms), the launch screen fades with a slight zoom (`FADE`: 300 ms, at 860 ms), then Today's blocks rise in, top to bottom, on `gentle` 45 ms apart (`RISE`). `boot.js` calls `LAUNCH.start()` before the first draw and `LAUNCH.finish()` once recordings have loaded and `LAUNCH.minWait()` has passed (at most `LAUNCH.capWait()`). `restoreImport()` calls `LAUNCH.replay(then)` to replay it on Today, with the toast in `then`. Tab switches and coming back to the app never replay it; an update reload is a cold launch, so it plays.
  - **Where the bars live:** `#splash` in `index.html` is the icon's plain background (an inline WebP, `<img>`) inside `.sp-icon`, with the six bars as `<i>` elements placed over it. Their positions, sizes, colours and shadow were measured from `splash/logo.png` so the icon looks the same at rest as the real one; `css/app.css` (`#splash i`) has their width and shadow. If the icon changes, regenerate the background and re-measure the bars.
  - **Today's blocks** are the elements marked `data-rise` in `scrToday()` (and `pinnedCard()`, `backupNudge()`); they're risen in the order they sit on screen, so the iPad dashboard works too. Add `data-rise` to a new Today block to include it.
  - **Reduce Motion:** no pulses or rises, the launch screen fades in 200 ms. **Motion off** (the tests): it uses the old `.out` class exactly as before 3.13.
  - **`LAUNCH.busy()`** is true from launch until Today has risen; `fwPick()` returns nothing meanwhile, so the floating window appears after the rise.
  - Tests: `tests/test_launch.py` (motion on, Reduce Motion, motion off, import replay, the floating window, and the 3.4 first-frame checks at every size).
- **Motion details (3.14, `js/details.js`, `DET`):** everything only animates elements already in their final place, so nothing ever blocks a tap. With motion off or Reduce Motion every function returns straight away.
  - **Lists:** call `DET.arm()` just before a change that redraws (`DET.arm({stagger: true})` for a re-sort), and `render()` calls `DET.play()` afterwards. Rows opt in with `data-fk` (a stable key, e.g. `sg:<id>`; `sw()` rows get one automatically) and their group with `data-gk`. Removed rows leave a `.det-ghost` copy that shrinks away (pointer-events none); groups ease to their new height; rows that move slide (a ripple when staggered); a row that moves into another group (a pin) travels as a copy so the group's `overflow:hidden` doesn't clip it. Today's `data-rise` blocks take part too (the backup reminder leaving). Add `DET.arm()` before any new delete, add, pin or reorder.
  - **Progress:** `updatePcard({dir})` is the animated version (range: `dir 0`, arrows: `-1`/`1`); `updatePcard()` with no argument (scrubbing) never animates. `DET.bars()` reads heights before the redraw, `DET.pcardIn(was, dir)` ripples from them (scaleY from the baseline, `BASE` in details.js must match `H - B` in `chartSVG`).
  - **Today:** `LAUNCH`'s `done()` calls `DET.todayIn()` (arch `stroke-dashoffset` fill, week row wave). `finishSession()` calls `DET.finished()`, and `DET.after()` (end of `render()`) pops today's circle once Today shows with no sheet. It also slides in pinned songs that weren't on Today last time (`data-fk="tp:<id>"`).
  - **Elsewhere:** `DET.calendarIn()` after opening or changing month; `go()` calls `DET.stepIn(DET.stepDir(from, to))` between Foundation, Rotation and Application; `DET.listIn()` after the All sessions switch; `DET.exLine()` after switching an exercise to History; `DET.takeIn()` / `DET.starPop()` for takes; `DET.dockSwap()` brings the song's bottom capsules in on a mode change only (never on a hint step or redraw).
  - **Recall wave:** `DET.hxSnap()` before a hint change, `DET.hxWave(was)` after: newly hidden words get `--hxd` delays (30 ms a word, in reading order, used by `.hxin .hx` / `::after` in app.css), newly shown words fade from the end backwards. `peekLine()` and the hold call `DET.peek(line)` for a small `ripple` spring.
  - **Sheets changing in place:** `renderSheet()` treats `exporting` → `exportReady` as the same sheet (`DET.inPlace`), so it doesn't rise again; `DET.sheetSwap(oldH)` eases its height and fades the content.
  - **Reduce Motion in CSS (3.14; class-based since 3.21):** the old blanket `* { animation: none; transition: none }` is gone. Under `html.motion-reduced` (set by `MOTION.publish()` from `MOTION.reduced()`, so the in-app choice works too) every transition is limited to opacity and colours over 0.2 s, and the elements whose keyframes moved things (`.sheet`, `.notebox`, `.clock`, `.ctxmenu`, `.lgdraw`) swap to the plain fade `rmIn` (`.clock.out` to `rmOut`; `.knob.squish` to none), at the end of app.css. **Don't use `@media (prefers-reduced-motion)` in new CSS:** use `html.motion-reduced`, and add any new moving keyframe's element to that list.
  - **Not built yet (left for later):** the section lift while reordering (Annotate's menu blooming from the word was replaced by 3.27's marks sheet), Perform's larger text scaling (FLIP), the recording bar rising, the progress dashes filling and the step pill moving onto the shared springs.
  - Tests: `tests/test_details.py` (motion on in slow motion, Reduce Motion, motion off). `daily()` seeds a session on each of the last 15 days so the checks don't depend on the day of the week.
- **Card zoom (3.15, `js/zoom.js`, `ZOOM`):** a card that opens a page zooms into it; Back shrinks the page into the card, with the list scrolled back to where it was.

### Recordings

Each take in IndexedDB is `{id, songId, created, len, size, type, star, blob, note?, o?}`. `o` is the place in the song it was recorded from (an `order` entry); takes without one (song practice, and everything before 3.9) belong to the whole song. **Since 3.20 every take is kept:** the keep rule (`prune()`, `KEEP_TAKES`) is gone, and nothing removes takes automatically. Recording a section uses the same `startRec`/`stopRec`/`saveRec` as song practice, with a `{songId, o}` target; while it runs, `rec.o` locks the song screen to it. **A section take starts (or carries on) song practice for that song** (`rec.sp`): `X` is made with `newSong()` if there's none, timed from the take (`X.start = rec.started`), and the take joins `X.takes`.

- **Mono (3.20):** `monoStream()` (session.js) mixes the microphone down to one channel through a `MediaStreamDestination` (`channelCount 1`, explicit) before `MediaRecorder`, unless the track already has one channel; if the context won't run within 400 ms it records the microphone as it is, so a take is never lost to it.
- **Names and comments** live with the song, not the take: `sg.takeNotes = {<take id>: {name?, comments?: [{t, text}]}}`, checked by `cleanTakeNotes()` (takes.js) from `cleanSong()`, so they're in every backup, even with Exclude recordings. Plain strings, for Search's Takes group (Render 10). Deleting a take (`TAKE.del()`) removes its entry.
- **On the device only** (`vocalTakeExtras`, stores `peaks` and `mono`, keyed by take id): `TAKE.analyse(id)` decodes a take once (22.05 kHz) into 50 peaks a second and measures each channel. If one is near-silent (under 3% of the other's RMS) it writes the live channel as a 16-bit mono WAV (`mono`), and `playTake()` plays that (`TAKE.blobFor(t)`) through the same `<audio>` path, so one sound at a time, the window, the lock screen and the silent switch behave as before. **The original recording is never rewritten.** New takes are analysed when saved; older ones in the background after launch (`backlog()`, one at a time), which also tidies extras for takes that have gone.
- **The takes sheet** (`sgTakes`, `TAKE.sheet(sd)`): `sd = {k, o?, all?, fresh?}`. With `o`, a segmented switch (`tkTab`) between the section and All takes; from the header's **Takes · n** button (`TAKE.headBtn(sg)`, beside the title, `tkOpenAll`) it opens on All takes. Rows newest first; tap (`tkTap`) expands one and plays it. The expanded take (`openId`) has the name (`tkRename`, inline), star, collapse, the comment pop-up strip (`#tkPop`), a canvas waveform (`#tkWave`, `data-own-gesture`, follows the finger), dots, times, −5 / play / +5 (`tkSkip`, clamped) and the comment field. Nothing is redrawn while a take plays: `TAKE.frame(player)` (from `playTake()`'s loop) and `TAKE.paint()` update in place. A take that ended plays again from 0:00.
- **Comments:** the first character typed locks the playhead time (`draft.t`); the chip (`#tkStamp`) opens −1 s · +1 s · Use current time; clearing the field lets go. Enter or Post saves `{t, text}` (≤ 200 characters), sorted. While playing, a comment pops up for about 2 s when playback crosses it (`prevT < t ≤ now`, and only within 0.6 s steps, so scrubs and jumps never do). Hold a comment: Edit · Delete (`sgCmtMenu`).
- **All takes as fold-out rows (3.26, Q10):** on All takes, when the takes come from two or more sections, `groupsFor()` makes a row per section in song order (`.tkfh`, `tkFold`, with its count and a chevron that turns down), with takes from no section last as Other takes. `folds` (a Set of `o`) holds which are open; it's set when the sheet opens (the expanded take's section, else the section the sheet came from, else none) and cleared when it closes. An expanded take's section is always open; shutting a section collapses its expanded take. Opening one turns the chevron and ripples its takes in (`gentle`, rows 45 ms apart); shutting fades them out quickly first. Takes inside sit on `--bg3`. A section's own tab, and All takes from a single section, stay plain lists.
- **Swipes and hold:** collapsed rows only. A sideways move claims the row (vertical scrolls the sheet; the sheet's own drag is only on its header). Right shows only Star (orange), left only Delete (red): a short swipe leaves the 84 px button, past half the row it acts (Delete always confirms, `sgTakeDel`). Hold 500 ms: Star · Rename · Delete (`sgTakeMenu`). The tap that ends a hold is swallowed, so it never lands on the menu that opened.
- **Review old takes** (`sgReview`, from Settings › Storage): unstarred takes with no comments, oldest first, each with a delete that confirms.

### The floating window

Since 3.12, `js/window.js` shows a small window on every screen outside the thing it's for. It's its own element, `#fw`, added to `<body>` and kept across redraws; **it must never go in `#layer`**, or the sheet scroll guards (`overlayOpen()` in gestures.js) would treat it as an open sheet.

- **One sound at a time (3.20):** every sound starts through `NOW.start(kind, id, stop)`: takes (`playTake()`, `nowTake()`), recording (`startRec()`, kind `rec`), the coach video (`COACH.play()`, or its `play` event when it's in `#app`), the track (`TRACK.play()`, also from song rows) and play-along (`ckPlay()`). Starting one calls the last one's `stop` and marks its window closed (`FW.dis`). `NOW.stop()` stops whatever plays (recording uses it); `NOW.ended(kind)` when a sound ends or stops itself. The lock screen's play and pause follow `NOW.last()`. There are no pairwise pauses any more: anything new that makes sound must start through `NOW`.
- **✕ and closed windows (3.20):** every sound kind has `close()` and the default window draws a ✕ (`fwX` → `fwClose()`); the video's own draw has it too, playing or paused. `FW.dis[kind]` keeps a kind out of `fwPick()` until its next `NOW.start()` (an explicit play); nothing else clears it: tab switches, redraws, sheets, `fwUpdate()`, the app coming back or a reload. `FW.shut` (set by ✕) keeps every kind, sessions included, off the current screen; `go()` clears it. A sound paused anywhere but the window or the lock screen (`FW.winAt`, set by `fwToggle` and the lock screen handlers) is closed too (`fwPaused(kind)`), so the window shows a sound while it plays and when paused from the window. A sound that ends leaves (each `active()` is false once ended). The session kind has no ✕ and its own screen now includes the song page of the song it practises.
- **Kinds:** `FW_KINDS` lists what can be shown, in the order they win (since 3.19: take → video → track → clock → session): `take` (a take playing or paused from the window), then `session` (a session with a `start`; untimed song practice has none). Each has `active()`, `own()` (you're on its own screen, so it isn't needed), `info()` (its text, time and progress), `toggle()` (its button) and `open()` (back to where you were). If the winner is on its own screen, the next one is tried. Song Clock's "Playing along" can be added as a third kind.
- **Updating:** `render()` calls `fwUpdate()` last; a MutationObserver on `#layer` calls it when sheets, the clock or menus come and go; playback's play and pause events call it too. `fwTick()` only changes its text: every second for a session, and from the take's progress loop. It hides whenever there's a sheet, the clock, a recording, song search or a text field in use.
- **Where you were:** `FW.sess` is `{view, y}`, the session step last shown and its scroll (kept up to date by a scroll listener). `FW.take` is `{id, place}`, set by `playTake()` from `fwHere()`: the tab, view, song, sheet and its `sd`, mode and scroll. Opening restores them through `fwGo()`, which renders and then scrolls.
- **Takes:** `takePlaying(id)` is true only while a take is actually playing, so its own buttons show Play when it's paused from the window, and tapping them carries on. Closing a section's takes sheet stops a paused take but lets a playing one carry on.
- **Corners:** `FW.corner` is `tl`, `tr`, `bl` or `br` (default), kept in localStorage `vocalWindow`. `fwBounds()` measures the room each time: right of the sidebar (the `.dock`'s left and padding), below the top bar, above whatever is in the dock (tab bar, the session button or Recall's hint capsule). Dragging follows the finger with pointer events; on release `fwThrow()` picks the corner from where it is plus 0.2 s of its speed, and springs there with `MOTION.spring()` on `nav`, starting at the finger's speed. There's no tucking against the edge.
- **Motion:** it rises in on `gentle` and shrinks out a little quicker; with motion off or Reduce Motion it just appears.
- **Hiding always finishes (3.17):** `fwHide()` sets a fallback timer (`FW.hideTimer`, the fade's duration plus 120 ms) that hides `#fw` even if the fade's `onfinish` never fires, and a later `fwHide()` with nothing shown hides a window left on screen. On iPhone the coach ✕ could leave the window up with a black video area. test_coach's `dismiss()` stubs `MOTION.animate` so fades never finish and checks the window still goes. `MOTION.spring(from, to, v, {spring, frame, done})` is a JS spring that starts with a speed, for anything thrown.
- **Tests:** `tests/test_window.py`, and the random-tap test checks it never shows over a sheet, while recording or on its own screen, never leaves the screen, and is there whenever a session is running elsewhere.

### The coach video

Since 3.16, `js/coach.js` plays the coach's video from a copy on the device. The repo is public: **never commit the real video or any course media.** Tests use synthetic WebM files in `tests/fixtures/` (Playwright's Chromium can't play H.264).

- **One video element.** `<video id="cv" playsinline>` is made once, with its `src` an object URL of the stored Blob. `render()` replaces `#app` with innerHTML, so the video must never stay in `#app`: `render()` calls `COACH.park()` first (into `#cvHold`, off screen on `<body>`), and `fwUpdate()` calls `COACH.place()` last, which moves it into the screen's `.cv-slot`, else into the floating window's `.cv-fw`, else back to the holder. Moving it within the same task doesn't pause it (checked in test_coach). Zoom copies swap any `<video>` for a dark box (`scrub()` in zoom.js).
- **Chapters** (3.16.1): `COACH_TIMES` in content.js, keyed by exercise id, holds where each exercise starts, from the YouTube timestamps (`'m:ss'` or `'h:mm:ss'`). coach.js builds `COACH_CH` from it, numbered in order of start (`COACH_CH[n]` is `[start]`, or `[L1, L2, L3]` when three times in order are given) and `COACH_MAP` (id → number). Keyed by id, so names never need to match the video's. Exercises with one time have no level picker; Loop repeats the whole exercise and the scrubber is one segment. `COACH_END` is 4773 s; a video within `COACH_SLACK` (10 s) of that length uses the chapters, anything else is a plain video. `COACH.at(t)` gives `{n, id, l, lv, s, e}` (`lv` is 3 or 1). The 3.16 times read from the video's slides were a few seconds late and are no longer used.
- **Current level:** `COACH.level(id)` is this session's level for it, else the latest logged level, else 1.
- **Player page:** `U.view = 'coach'`, Back goes to `U.coachBack` (the exercise page or the tab it was opened from). While playing nothing is redrawn: `paint()` updates the scrubber, times, title and level picker in place (motion rule 8); crossing into another exercise redraws the page once. The scrubber (`#cvScrub`, `data-own-gesture`) follows the finger at once and maps segment by segment, gaps included.
- **Loop** jumps back to the level's start when playback reaches the next level's start. **Speed** cycles `COACH_SPEEDS` with `preservesPitch`.
- **Doors:** `COACH.exercisesRow()` (Exercises tab, `data-zk="coach"`), `COACH.exerciseRow(id)` (Summary tab, `data-zk="coach:<id>"`), `COACH.stepHTML(view)` (Foundation and Rotation). In a session the slot shows once tapped, flagged by `X.cv` on the draft. `go()` calls `COACH.stepped(was)`: moving between steps cues the new step's first exercise (`stepEx`), paused; Application has no chapter, so the video pauses there.
- **Floating window:** the kind `video` sits between `take` and `session` in `FW_KINDS`. It has its own `draw()` (fwDraw hands over to it), holding the real video. `active()` needs a play since the app opened (so last time's paused video doesn't pop up after a reload) and no ✕ since. **Only a play you asked for clears ✕ (3.17):** `COACH.play()` (Play, Play with coach, the window's button, the lock screen) clears `dismissed`, and so does the video's `play` event when the video is in `#app` (its slot, or full screen from there). A `play` event while it waits in `#cvHold` never does. `own()` is the player page or a screen with a `.cv-slot`.
- **One sound at a time:** `playTake()` and `startRec()` pause the video; playing the video stops a take.
- **Tests:** `tests/test_coach.py`; the random-tap test runs with the video added and checks there's only ever one `<video>`, that it's in its slot, and that its window never shows on its own screen.

### Song Clock

Since 3.18, `js/clock.js` times a song's lyrics. **Timing says when; marks say how:** timing is its own layer on the song (`sg.timing`) and never changes the lyrics, sections, marks or takes. Built so far: phase A1 (play-along, Check timing, the header and grid), Q02 (section starts set on the track's waveform, play-along from the track: see The track player) and **Q05 (3.28, Song Clock: Tap Re-Anchor): timing runs off the song's own track on this device.** Lines are placed on the track's waveform (the line lane), fixed while playing along (punch-in), flagged with a track marker, and reached from a hold menu on any lyric line. Sync by sections (tapping along to music on another device) and play-along without a track are retired; Q06 was folded into Q05. Q07 (paced Recall) builds on it.

- **No timing without a track (Q05):** `ckCan(sg)` is `TRACK.has(sg.id)`. Without it the Timing tile and pinned icon read **Add a track to time this song** and open the track picker (`ckAskTrack()`, the song's Track row's door); `ckOn()`, `ckPlay()` and `CLOCK.after()` refuse or turn play-along off. Timing saved on an older song (or with its track on another device) is kept untouched and shows on Check timing, with a note that play-along needs the track (Ivan, 30 Oct 2026). Timing on an untimed song with its track goes straight to the track player (`ckRetime(sg, 0)`).

- **Data:** `timing = {len, real, est, slots}`. Times belong to **places in the running order** (`o`), not sections, since Chorus 2 is sung at a different time from Chorus 1 (marks are the opposite: once per section). Each slot has one `[start, end]` per line of its section (`end` may be `null`), `anch` (the section's start is set: from a marker made a section start, or a section's first line placed by hand) and `marks` (to-do markers, line numbers). Q05 adds two optional lists of line numbers (older versions drop them, harmlessly): `fix`, lines placed by hand on an estimated song, and `sb`, **suggested breaths** (see below). `len` is the song's length (whole seconds, up to 20:59). `est`: lines were spread evenly from section starts; a line stays estimated until it's in `fix`, and the song stops being `est` once every line is (then `fix` is dropped). **Q12:** moving a timed section (`ckMoved(sg, o)`, from `sgEndDrag`) uses the same fields: the song becomes `est` with every other placed line in `fix`, so only the moved place's lines are estimates (its start kept), with no new field. `real`: the clock matches the music app's song time (unused). The schema stays 4.
- **Checking:** `cleanTiming(t, sg)`, called from `cleanSong()`. It drops slots for places no longer in the order, extra lines, junk, bad markers and set starts, and any line that starts less than 0.1 s after the one before (an end that overlaps the next start is trimmed). `fix` and `sb` are checked like `marks` (in range, no repeats, sorted); a suggested breath also needs its line timed and goes once the line has a breath mark of Ivan's. Nothing in it can break the song.
- **The maths** (all in clock.js): `ckLines(sg)` lists every line in running order with its syllables (vowel groups) and whether it has a breath mark of Ivan's. `ckRaw()` reads the saved times; `ckFill()` gives every line a time to play from (lines without one are spread between their neighbours; Q12: with no room, as between two touching lines, they're squeezed between the two starts so neither moves) and `ckOrder(T, placed)` keeps the estimates in order (each starts ≥ 0.1 s after the last, the last one's end is trimmed, and every line lasts ≥ 0.1 s). **Q12: `ckOrder` never rewrites a placed line** (the `placed` mask); placed lines out of order stay as they are and `ckOverlaps(M)` flags them on Check timing (**Overlaps**). Without a mask everything counts as an estimate. `ckEnd()`: a missing end is the next line's start or 0.3 s a syllable, at least 1.2 s. `ckSpread()` spreads each section's lines by syllables between set section starts. Q12: every section before a set start fits in before it (ending a second early): at their natural pace if they fit (the last stretched to fill), else squeezed together; with no room at all (under 0.2 s a line) they're left without times, as estimates. A set start's first line is never pushed. `ckWarp()` stretches piecewise-linearly through set points (a plain shift outside them). `ckModel(sg)` bundles all of it, with (Q05) `est[i]` (estimated: no time of its own, or spread and not placed) and `sb[i]`, and (Q12) `placed[i]` (a time Ivan set: a line placed by hand, or a set section start's first line) and `anch[k]`, which only counts while the section's first line has a time. **Writers read `M.raw` with `M.placed`/`M.est`, never the filled `M.T`** (that's for play-along and drawing). `ckBounds(M, i)` is the starts of the nearest placed lines either side: the only limits for punch-in, Start here / End here and lane drags (none if those lines are out of order). Presses have `CK_LAG` (0.15 s) taken off.
- **Writing:** `ckStore(sg, L, T, anch, marks, flags, fix)` writes every line, keeps `fix` as it was unless given, clears `est` once every line is placed, and works out `sb` from scratch: a gap of at least `CK_SB` (0.25 s) between a placed line's end and the next placed line's start, on a line with no breath mark of Ivan's. **`ckSetLines(sg, {i: [start, end]})`** is the one door for fixing lines in place (the line lane, Start here / End here, punch-in): `ckSnap`, the saved times with the changes, the lines become placed, lose their to-do marker, a section's first line sets its start; the placed line before ends by the new start and the line's own end comes by the next placed start (Q12: only next to what changed); then `ckStore` and a "Re-timed “…”" toast with Undo. It refreshes whatever shows the timing (`TRACK.refresh()` in the player, else a redraw or `CLOCK.after()`).
- **Retime** (`ckRetime(sg, i)` → `TRACK.retime(id, i, t)`): the track player in Line view, the playhead on line i's start and its block selected, pushed in from a song page or Check timing (`ZOOM.armPush('trk:retime')`); Back returns there (`TRACK.back()` remembers Check timing). Its doors: every Check timing line row, its Section starts row and Time each line (the first estimated line), the hold menu's Retime line, play-along's Retime (paused) and Timing on an untimed song.
- **Sync by sections is retired (Q05):** its screen (`ckSync`), pad, clock (`CK.sc`, `CK.P`) and the Sync again tile are gone; a pinned `sync` is dropped by `ckPrefs()`. `ckSpread()` stays (a marker promoted on an untimed song spreads the lines).
- **Play-along:** `CK.on` for `CK.songId`, clock `CK.pc`. ### The track player

Since 3.19, `js/track.js` plays a song's real track for drilling: import it from Files, see its waveform, zoom, scrub and loop a phrase slowly with the pitch kept. The repo is public: **never commit real music.** Tests write synthetic WAV files (tones with gaps) into `tests/output/`.

- **Data:** `sg.track = {name, dur}` and `sg.loop = {start, end, on}` live in the song (backed up). `cleanSong()` checks them; `cleanLoop(l, dur)` (track.js) needs numbers ≥ 0, clamps the end to the track's length and drops a loop shorter than `TRK_MIN` (0.5 s). The schema stays 3: the fields are optional and older versions keep fields they don't know. The audio and its peaks are separate entries in IndexedDB `vocalTracks` (stores `audio`, `peaks`, keyed by song id). `TRACK.load()` (boot.js) lists which songs have one (`have`).
- **Importing** (`add()`): `<input id="trackIn">` with each format named in `accept` (3.19.1: iOS greys out audio files in Files for `audio/*`), opened by `TRACK.pick(id)` (or `pick('draft')` for the + sheet's Add media, 3.20: the file is read with `TRACK.read()` and kept on the draft; `TRACK.attach(sg, file, r)` stores it only on Save). Over `TRK_BIG` (60 MB) it asks first (sheet `trkBig`). The file is decoded **once** with an `OfflineAudioContext` at 8 kHz (falling back to 22.05/44.1 kHz if refused) and reduced to 50 peaks a second (`Uint8Array`, scaled to the loudest). A file that won't decode says `TRK_BAD`. Replacing keeps the loop (trimmed to the new length) and timings; a length more than 1 s different shows `TRK_LENGTH`. **Q12, a shorter track:** `attach()` takes `ckSnap(sg, true)` first (Undo puts the timing, markers and loop back) and counts markers past the new end (start or end) and lines starting at or after it (`ckPast()`). If there are any, `past` is set and sheet `trkPast` asks: **Trim to the new track** (`trkPastTrim`: `cleanMarkers` against the new length, and `ckTrim()`: those lines lose their time with a to-do marker, a first line takes its set start with it, nothing ends after the end) or **Keep them** (`trkPastKeep`, also what closing the sheet does). Both toast with Undo. `cleanSong()` no longer trims markers to the track's length, so kept ones survive a reload. Opening the player never decodes again (`open1()` reads the saved peaks; it decodes only if the peaks went missing, and saves them).
- **Playback:** one `<audio>` (not in the DOM), `playbackRate` with `preservesPitch` (and the webkit/moz names). Not `AudioBufferSourceNode`: its gapless loop would shift the pitch when slowed. The loop is checked every animation frame (`frame()`): when playback crosses the loop's end (`prevT < end ≤ t`), it seeks to the start; a small gap there is accepted. **Q09:** `armWrap()` (from each frame, `timeupdate`, `play` and `seeked`) sets a timer once the end is under `WRAP_SOON` (0.3 s of real time, at the current speed) away, so the jump back (`wrapTo()`) lands within a few ms of the end instead of up to a frame late (or a `timeupdate` late, locked); the frame and `timeupdate` checks stay as the safety net, so no boundary is missed. Still one `<audio>` with its pitch kept: a second element or Web Audio would fight the lock screen, one sound at a time or the pitch. `TRACK.wraps()` lists the last 30 wraps (`{t, start, end, rate, by}`) for the tests. Play with the loop on from outside it starts at its start. `seek()` sets `prevT`, so jumping past the end never counts as crossing it.
- **The page** (`U.view = 'trk'`, `U.songId`): `TRACK.page()`, `TRACK.bar()` (Back, title, ⋯ for sheet `trkMenu`: Replace track…, Remove track → `trkDel`, Clear all markers, and (Q02) the jog wheel's side), `TRACK.dock()` (the transport `.trktr`: back to loop start, play, loop; in Markers (Q09) `.trkmd`, a row of pills `.trkmp` (Backing Sound `trkSnd`, Loop `trkMdLoop` with id `trkLoopB`, so `paint()` keeps it) over three pads `.trkpads`: Replay `trkReplay`, Play/Pause `trkPP`, Next `trkNext`, 95:140:95 px, shrinking in proportion when narrower; all in `#dock`, so `fwBounds()` already avoids it, and `main` gets more bottom room while `.trkmd` is shown). Everything that changes with the level is `#trkBody` (`bodyHTML()`, redrawn in place by `body()` on a level change, which also calls `renderDock()` when Markers is entered or left). Levels are `TRK_LEVELS` (Q02): Phrase (6 s) and Line (16 s) are a strip (`#trkStrip`, 148 px, playhead at `TRK_HEAD` 40%, `#trkC` canvas) with the lyric card `#trkCtx` above it; Song is the Song card `#trkSong` (Q09: its heading `.trksh` with the length, and the **Lyrics** pill `trkSongLyrics` at its top right when the song is timed) holding `#trkRows`: 24 s `.trkrow` buttons (gutter and canvas; the last row ends at the track's end), each followed by `.trkly` (its lines, `trkLyr` seeks) when `vocalSongPrefs.trkSongLyrics` is on and the song is timed; Markers is the grid `#trkGrid` (`gridHTML()`). A level saved before Q02 is reset once to Line (`trkLvV` = `TRK_LV_V`). Everything is drawn on canvases sized with `devicePixelRatio` (`draw()`), every frame while playing or dragging; text and buttons change in place (`paint()`), so nothing is redrawn while it plays.
- **Fingers:** on the strip a pointer near a handle (22 px either side) drags it (`dragHandle()`: past the other they swap, never closer than 0.5 s, saved on release); anywhere else it scrubs (the waveform follows the finger). Two quick taps outside the loop clear it. The jog wheel moves `dy × window / TRK_JOG` (300) seconds, down is later. **Q02:** `vocalSongPrefs.trkJogPos` is `right` (default), `left` (`.jog-left`: the canvas starts 48 px in) or `bottom` (`.jog-bottom`: the canvas is full width and `#trkJog` is the roller `.trkroll` under the strip, `dx`, right is later). The roller doesn't grow. A row tap seeks there and stays in that view (3.20; `showHead()` keeps the playhead's row in view after a level change). Pinch (touch events, `TRK_PINCH` 40 px a level; also listening on the touched elements, since a level change replaces them) and Ctrl+wheel (a Mac trackpad pinch) change level. ### Marks

Since 3.27 (queue item Q03), marks come in four layers, one per stage of learning a song, plus a Note on every layer. Only one layer shows at a time. `js/marks.js` (`MARKS`) holds the data side and drawing; selecting words and the marks sheet are in songs.js.

- **The marks** (`MK_DEF`, `MK_BY`): **Notes** (Pitch, Slide, Hold, Ornament, Rhythm), **Phrasing** (Phrase, Chain, Peak, Breath, Shape), **Words** (Vowel, Carry, Onset, Stress, Say), **Delivery** (Register, Colour, Vibrato, Mic, Intention), and **Note**. Each has its options (`opts`), whether options take text (`txt`) or need it (`need`: Sing as…, Say, Intention), and where it lands in a selection (`at`, `mkAt()`): Peak, Onset, Colour and Register (except Flip here) on the first word; Phrase, Stress and Shape keep the range; Intention belongs to the section; the rest go on the last word.
- **Data:** each section's `marks` is `[{id, L, type, opt, line, w0, w1, text, check?, was?}]`, stored once per section, so every repeat of a linked chorus shows the same marks. `L` is the layer (`'note'` for Note) and must match the type. `line` is `-1` for Intention (one per section). `w0 ≤ w1` are word indices within the line. `text` is up to 80 characters (Notes 200). `held` is marks whose word was removed: `{id, L, type, opt, text, was}` with no place. `mkCleanSection()` (from `cleanSection()`) drops only bad marks (unknown type, wrong layer, unknown option, missing required text, out of range, a second Intention), puts a one-word mark given a range on its word, removes exact duplicates, and keeps fields it doesn't know.
- **Moving the older marks across** (`mkMigrate()`, data step 4, and any section that arrives with `ann` and no `marks`, such as an old backup): `up`/`dn` → Notes · Pitch · Up/Down, `run` → Notes · Ornament · Run, `br` → Phrasing · Breath, `v` → Words · Vowel · Sing as… with its text, `nt` → Note with its text; `check`/`was` carry over to each; anything else on an old mark becomes a Note carrying its name and value. `orphans` become `held`.
- **The older copy** (`mkMirror()`): every change to a section's marks redoes `ann` and `orphans` in 3.26's shape (breaths, runs, pitch up/down, vowels with text, Notes), so a new backup still restores in 3.26 ("data changes are additive"). Anything that changes `marks` or `held` must call `MARKS.mirror(sec)` (`MARKS.add`, `MARKS.remove` and `relink()` do). Marks added in 3.26 after a 3.27 backup was restored there aren't read back: this version only reads `marks`.
- **Following their words** (`mkRelink()`, from `relink()`): each word is matched by `align()`; a mark moves with its word; a changed word moves it to the new word with `check` and `was`; a removed word sends it to `held`. A range keeps the words still there (on the first remaining word's line) and is flagged if any changed or went. Checks count towards the pencil's badge (`MARKS.checks()`).
- **Drawing:** `MARKS.line(sec, li, show, word, wrapCls)` draws one line for any view: `mkDeco()` works out what each word wears from the marks `show` lets through: labels above the word (`mkLabel()`, joined with " · ", the Peak's `^` first, `MARKS.labRow()` in the 3.17 `.v` style), classes (`mhold`), glyphs after it (breath `.m.br`, Sneak smaller `.sn`; chain `.mchain`; carry `.mtie`; Note `.m.nt`), and the ranges: a Phrase's bracket `.mph` and Stress's line `.mst` are backgrounds on a span round the words (spaces included), so the line is unbroken and nothing moves. `word(wi, w, deco)` is each view's own word element. Note text shows under its line (`.sgnote`); Intention is `.mint` under the section label. A just-added mark fades in once (`MARKS.fresh`, `.mkfresh`).
- **Which marks each view draws** (`MARKS.show(kind, layer)`, `sgShow()` in songs.js): Practise and the Marks side: the chosen layer plus Notes (`'layer'`). Recall: Phrasing's brackets, chains and breaths, plus Notes (`'recall'`); no labels, so nothing moves between hint levels. Perform: what Marks while playing allows (`'none'`, `'breaths'`, or `'active'`: the layer plus breaths, never Notes). Play-along: see Song Clock. The track player's lyrics stay plain (decided at Render). Search's Lyrics group searches the words only.

### Rules that keep old data working

- **Never rename or remove an exercise id** (`slides`, `humming`, `lip`, `straw`, `falsetto`, `upperlower`, `rung`, `hinge`, `half`, `vertical`, `nasal`, `flex`). Sessions store levels by these ids. The backup tests fail if they change.
- **Data changes are additive.** Add fields with a default; don't rename or repurpose existing ones. Older backups must still restore, and new backups must still restore in the previous version.
- **Bump the IndexedDB version only to add stores**, and create each store only if it's missing. Every database opens through `IDB.define()` (storage.js, Q11); don't write another copy of the open and transaction code.

## Backups

A backup is a JSON file with: a plain-English `README` array, `app`, `format` (2), `appVersion`, `exportedAt`, `device`, `summary`, `data` (= `D`), `draft` (= `X`), `takes` (recordings as data URLs) and `checkCode`.

- **Exclude recordings** writes `takes: []` and `recordingsExcluded: true`, and the check code is worked out on that file as written. Check a backup and Import say "Recordings not included", and restoring one keeps the device's recordings (the undo copy notes `keptTakes`, and undoing leaves them alone).
- `checkCode` is the SHA-256 of `JSON.stringify({data, draft, takes})`. `inspectBackup()` recalculates it to decide whether a file is complete (`good`), from before 3.6 (`old`), edited or partly copied (`changed`), missing some recordings (`partial`) or unusable (`broken`).
- Export reads its own file back through `inspectBackup()` before offering to save it.
- Restore keeps an undo copy first; `undoRestore()` puts it back.
- Files are named `Vocal Sessions backup · YYYY-MM · Device.json`, so iOS offers to replace the month's file.

The fixtures in `tests/fixtures/` are real backups made by 3.5 and 3.6, plus a copy of the 3.6 app. **Don't regenerate them.** They prove that old backups keep working, and that new backups still open in 3.6.

### Search

Search (3.22, `js/search.js`, `FIND`, queue item Q01) finds anything from one place.

- **Doors:** a circle beside the tab bar on every screen that has the tab bar (`FIND.circle()`, drawn by `renderDock()` in a `.dockrow`; it stays beside the bar when the bar shrinks), the end of iPad's top capsule (`FIND.capsuleBtn()` in `topTabs()`), a Search row at the top of the wide sidebar (`FIND.sideRow()` in `renderSide()`), and Cmd+F (Ctrl+F off Apple devices; a `KEYS` shortcut in songs.js). All call `FIND.open()` (`findOpen`). It isn't a `TABS()` entry, so Cmd + 1–4 are unchanged.
- **It's a tab of its own:** `U.tab = 'find'` with no view (`FIND.page()` from `render()`; `tabOf('find')` matches no tab, so no tab is selected and the circle is, `.on`). Being a tab means every Back that goes "to where you came from" lands on the results: a song opened with `sgOpen` and `data-v="find"` sets `U.sRet = 'find'`, an exercise's `U.prevTab` is `'find'`. ### Keyboard (3.31, Q13)

Shortcuts from an iPad keyboard or a Mac never fire twice, while typing, or during a recording. Everything is in `KEYS` (helpers.js):

- **One typing check:** `KEYS.typing(e)` is true when the key's target, or whatever has the focus, takes text (an input, textarea, select or anything contenteditable). Nothing else writes its own (`tests/test_keys.py` checks the old copies are gone).
- **One place shortcuts go through:** a shortcut is `KEYS.add({when, run, repeat, typing, busy})`. gestures.js registers the only listener, `document.addEventListener('keydown', KEYS.route)`, after every other file's keydown listeners, so it sees what they did. `route()` skips a key that's `defaultPrevented` (another control used it) or `KEYS.composing(e)`, then gives it to the first shortcut whose `when(e)` is true, unless that shortcut is blocked by typing (`typing: true` allows it) or by `KEYS.busy()`, a sheet, the length picker (`CK.pk`) or a recording (`busy: true` allows it). It calls `preventDefault()` and runs it, except a held key (`e.repeat`), which only runs shortcuts with `repeat: true` (moves, never toggles).
- **The shortcuts:** Cmd + 1–4 (gestures.js; not on a session's step, `X && isFlow(U.view)`, and through `sgTabTap()` like the tab bar), Cmd + F, N, E and , (songs.js, `typing: true` as before, so Cmd+E is still Done while editing the lyrics), ↑ ↓ between songs (songs.js, `repeat: true`), and the track player's Space, I and O and its ← → (`repeat: true`) in track.js. Add a new shortcut the same way.
- **Cmd only on Apple devices:** `KEYS.mod(e)` is `metaKey` without Ctrl on an iPhone, iPad or Mac (`KEYS.apple`, from the platform or user agent; an iPad asking for the desktop site says Macintosh) and `ctrlKey` without Cmd elsewhere, so Ctrl+E, N, F and the rest stay text editing. Tests on the iPhone user agent press `Meta+…`; with `ua=None` (Linux) they press `Control+…`.
- **Controls keep their keys:** the length picker's wheels call `stopPropagation()` on ↑ ↓ (they used to open the next song too, and Set then went to the song the picker was opened on). A new control that uses a key should `preventDefault()` (and `stopPropagation()` if a document listener could also act on it).
- **Enter to confirm** uses `KEYS.enter(e)`: Enter, but not while composing (`isComposing`, or keyCode 229, which Safari gives the Enter that picks a word). Used by Search's field, the Songs filter, the title and artist in place, a mark's text and a take's comment and name.
- **Escape isn't a shortcut:** songs.js (capture), clock.js, search.js and events.js close the same things as before, in the same order.

Tests reach into the app through its globals (`D`, `X`, `U`, `render`…), so the scripts must stay classic `<script>`s, not ES modules. `harness.offline(path)` switches the test web server off for a real "no connection" (Playwright's own offline switch doesn't reach the offline helper).

## Releasing

`python tools/release.py 3.7` updates `APP_VERSION` and `RELEASE_DATE` in `index.html`, the README badge and "Current version" line, and adds a `## 3.7 · date` section to `CHANGELOG.md` with a placeholder headline and note. The release test fails until both are replaced with the real headline and changes.

Version numbers: **major** for a redesign, **minor** for new features, **patch** for fixes.

The app checks for a newer `APP_VERSION` on pull to refresh, so a release reaches the phone the next time Ivan pulls down on Today or Progress.

## Style

The app follows Apple's design language for iOS 26/27 (Liquid Glass imitated in CSS), with British English in plain, friendly words. Everything must work on iPhone, iPhone landscape, iPad and Mac, in light and dark mode.
